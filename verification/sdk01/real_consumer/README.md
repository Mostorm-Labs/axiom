# SDK-01 consumer oracle candidate

This is a deterministic **draft oracle**, not a product run or accepted P20. `expected-v1.json` is manually specified without invoking the production codec, normalizer, planner, or SDK. `check_observations.py` compares normalized actual observations to the exact candidate expectation and rejects missing/extra fields, absent scenarios, duplicates, nonfinite values, changed excluded objects and wrong History/receipt results. A match is labeled `ORACLE_MATCH_ONLY`: it does not establish that input came from a real SUT or from Windows/Chrome.

Two separate real fixture sessions are required. They must use actual SDK and host owners; never feed the expected JSON back as the observation. The capture driver must bind each symbolic role to a distinct full object ID and retain that mapping with source revision, executable/library hashes, browser/version, inputs, commands, outputs and raw snapshots. Record a History baseline and normalize `history_cursor` as its signed offset, not the absolute pre-existing cursor. Each observable field must come from canonical or independently parsed real output, not by copying the SDK receipt; retain full unnormalized outputs for review. Any unavailable observation or ID mapping is a blocker.

* `partial_fill`: seed 3 distinct Shapes with explicit blue solid fill and 2 distinct Images; select all five. Verify exact supported/excluded roles and `not_applicable`; unknown permission and omitted explicit partial acknowledgment each cause no object or History mutation; apply red and observe exact receipt, excluded images, one Undo and Redo. `partial_not_acknowledged` is a normalized diagnostic for the current candidate `kCanvasSdkMultiInvalidValue` admission with a missing flag, not an invented new public enum.
* `stroke_width`: seed two Shapes with independent explicit solid strokes: A red width 5 round cap miter join, miter 4, dash `[2,1]`; B blue width 7 square cap miter join, miter 7, dash `[4,2]`; offsets 0. Submit only width 19 and check both colors, cap, join, miter, dash and fill are preserved through apply, one Undo and Redo. Fixture paint and initial state must be observed and validated before command submission.

The validator takes `--expected`, `--observed`, and `--output`; a frozen package must pin the expected and validator hashes and the real driver source, not allow the test executor to substitute a different expected file. Array order in observations is normalized by fixture role order. `tests` check the validator itself with synthetic in-memory data and do not claim SDK behavior. The installed-SDK harness, role-to-ID capture, independent snapshot decoding, Windows host and actual Chrome/WASM host drivers are not yet implemented. No API outcome, Windows result, browser result, or physical pass is established by this folder alone.

`run_observation_driver.py --driver <actual-driver-executable> --driver-sha256 <driver-sha256> --expected verification/sdk01/real_consumer/expected-v1.json --expected-sha256 <frozen-expected-sha256> --output <result.json> -- <driver arguments>` invokes the actual driver, appending `--output <fresh-absolute-path>`. The driver must write normalized observations matching the documented schema. With Node/Chrome, the driver is Node and the JavaScript test path and arguments follow `--`; the test script, browser, generated WASM, host executable and installed SDK must also be content-addressed in the surrounding evidence. The runner verifies the executable and expected hashes, records command, exit/stdout/stderr and raw observation hash/contents, rejects missing output, timeout, bad data or mismatches, and labels a matching result `MATCH_REQUIRES_PROVENANCE_REVIEW`, never product PASS. Synthetic scripts in the runner's own unit tests only check these failure paths and are not test adapters or product evidence.
