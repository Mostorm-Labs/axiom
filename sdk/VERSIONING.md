# Axiom 版本规则

Axiom SDK 使用 `x.y.z` 三段非负整数版本号，不使用前导零或 `preview` 等后缀。
本规则由产品迭代规模决定版本级别，适用于各平台 SDK、Demo、GitHub Release 和 npm 包。

| 字段 | 含义 | 升级方式 | 示例 |
| --- | --- | --- | --- |
| `z` | 小版本改进：问题修复、性能优化、UI 和体验完善等 | `z + 1` | `0.0.1 → 0.0.2` |
| `y` | 小功能迭代：新增独立的小功能，或对既有能力进行功能扩展 | `y + 1`，`z = 0` | `0.0.2 → 0.1.0` |
| `x` | 大功能迭代：新增或重构一组重要能力、主要工作流或整体产品能力 | `x + 1`，`y = 0`，`z = 0` | `0.1.3 → 1.0.0` |

同一次发布包含多种变更时，按最高级别升级一次。首次正式编号为 `0.0.1`；
本次已有功能作为首个版本的基线，不再因为打包时包含多项功能而改变用户指定的首发版本。

每次发布须同时更新 `sdk/version.json`、`sdk/web/package.json`、
`sdk/web/axiom.mjs` 和 `sdk/web/axiom.d.mts` 的版本标识。各平台构建、Demo 和包清单
必须来自同一提交、使用同一版本。GitHub 标签为 `axiom-sdk-vx.y.z`，普通 Release
标题为 `Axiom SDK x.y.z`；npm 包为 `@mostorm/axiom@x.y.z`，默认分发标签为 `latest`。

已发布版本、标签与文件不可覆盖。发布说明应记录迭代级别、功能与修复、验证结果及
兼容性变化。ABI、Operation、Snapshot 和 SDK 接口的兼容性由各自协议及发布说明明确
声明；发布编号不能替代这些兼容性约束或实际平台验证。
