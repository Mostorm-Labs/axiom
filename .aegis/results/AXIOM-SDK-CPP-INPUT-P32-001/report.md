# Installed C++ input and Shape style verification

The initial external Shape test failed to compile because the public Runtime did not expose the existing platform input contract. The implementation now delegates source registration/unregistration and complete `PlatformPointerBatch` facts to the same RuntimeComposition input ingress. It does not implement gestures or synthesize capabilities or pressure. The independently compiled installed consumer uses real down/move/up input to create two Shapes, assigns two distinct strokes and blue fill, selects them, reads exact root IDs and properties, changes width to 19 and checks per-object fields and one Undo/Redo. A mixed-source batch is rejected without semantic generation change and input after source retirement is rejected.

`raw/sdk-cpp-external-shape-green.json` preserves an initial test failure: the test incorrectly assumed an unknown source must fail, but existing Runtime intentionally auto-registers a first-seen source. The test was corrected to exercise the accepted mixed-source rule; production source was not changed to satisfy that incorrect assumption. The assets RED and later pass are retained. The installed Windows package includes ICU data and exposes an asset-copy helper; the consumer checks the file is present. Full application font/resource packaging remains unverified.

The final external three-test CTest run passes with no skips; the deliberately incompatible CRT configure is rejected. The test embeds expected values corresponding to the frozen P04 Shape scenario, but it does not yet produce normalized observations for the frozen `expected-v1.json` driver or establish both platform-host variants. Windows host/build and selected tests and actual Chrome/WASM selection regression results are recorded raw. Browser input is synthetic. This is not a full SDK-01, physical, Gate, release, or D07 OOM pass.
