## Regression root cause and decision required

The pre-existing facade test queues an opacity change from a selected-object snapshot, performs a direct stroke-width change on the same selected object, then expects the queued opacity edit to apply and preserve the new width. In contrast, the existing stale-selection guard added by `a6b68e36dacd95b64d9e23586c271db87edc901a` rejects when the captured semantic generation differs, even if the changed property is unrelated. `CanvasControlService::processPending` removes this stale request and returns a `kStaleTarget` terminal receipt without increasing its processed count.

An isolated diagnostic copied the unchanged test to `raw/facade-probe.cpp`, added only observation and early exit, and linked the real Runtime libraries. With assertions enabled (`/UNDEBUG`, matching the original target), the observed submission generation was **3**, current generation **4**, processed count **0**, receipt state **4 = kStaleTarget**, error **5 = kStaleTarget**, exit 0. `raw/facade-probe-confirmed.log` records it. A first diagnostic built with `NDEBUG` skipped side-effecting test setup assertions and yielded zeros/exit 1; `raw/facade-probe-initial-ndebug.log` preserves this invalid probe and is not evidence of Runtime behavior. The original regression remained unchanged and failed again when run alone.

The original oracle requires automatic preservation/merge of unrelated changes; the later guard requires revision-fenced rejection. Neither the old expectation nor the new rejection may be silently relabelled as the other. The concrete product choice is either (A) return stale, refresh and explicitly retry the field patch while preserving unrelated data, or (B) define a field-level conflict protocol that permits non-overlapping updates. A full SDK-01 verification package must bind the chosen result and retain tests for the other safety properties. No production fix or weakened oracle is authorized by this diagnostic alone.
