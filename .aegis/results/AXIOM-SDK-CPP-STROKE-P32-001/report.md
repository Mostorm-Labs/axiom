# C++ per-root stroke-width and read — initial slice

The exact source baseline and working-tree source hashes are recorded in `manifest.json`. The user requested this work; this is not an independent Control/Gate review. The actual RuntimeFacade delegates to the existing Composition, semantic operation and History owners. This implementation changes width on each eligible solid stroke separately, preserving each root's other stroke fields. The original whole-value property entry remains available. The new public read requires matching full eligible IDs, selection/generation stamp and known local permission. Mixed NoStroke/solid selections reject the width edit rather than silently excluding supported roots.

The raw RED logs show the missing width and per-root read methods before implementation. `sdk-cpp-stroke-final2.log` shows both real owner tests passed, with exact GTest names. Their independent assertions cover distinct colors, caps, miter, dash and fill, width 19, one Undo/Redo, stale/incorrect identity, invalid width, unknown permission and NoStroke rejection. `sdk-cpp-root-read-final.log` contains the 11 selected Windows CTest results, including native Debug UI invoking the mixed-width action. Actual Web WASM built and real headless Chrome regression produced 44 passing assertions; that browser regression does not exercise the new mixed-stroke UI action. The external installed lifecycle consumer still links and runs against the updated library. Physical input remains unobserved.

The evidence is narrower than full SDK acceptance. In particular the installed external consumer does not yet seed two styled objects and run this scenario, Windows native host and Chrome do not yet have an independent mixed-stroke host driver, and full API01–API12 plus P01–P10 remain unproven.
