# UR1c2 working-set repair design

Existing owner remains SkiaRenderer -> SkiaRenderCache + PreparedGeometryCache + SourceRetentionPool + ResourceBudgetManager. No consumer/semantic/input API changes.

1. Lookup stays lookup-only. Frame preflight retains a bounded set of demand dependencies in SkiaRenderCache, each charged for node/key/reference metadata. Keys retain complete immutable owner+pointee+type+command identity; existing source leases remain charged until bindings are pruned/rebound. Camera, masks and material do not invalidate world body progress. Source changes prune the binding before old group leases are replaced. Pending references survive RAF; clear/reset of the owning cache cancels them.
2. Common demands within index capacity retain ready dependencies through actual raster/Direct consumption. Discoverability eviction cannot force a leaf to synchronously rebuild history. Deferred jobs cannot be retired while pending and externally owned. Ready dependency lookup falls back to the held binding when alias discovery was retired.
3. A demand larger than the dependency cap, or a real byte admission denial while collecting dependencies, uses bounded staging in the same cache. Existing composite/scratch, preparationCursor and CompactStrokeRasterJob consume one qualified prepared body at a time in original z-order. Ready source geometry is released after consumption; optional prepared entries are reclaimable on real denial. No arbitrarily large whole-visible-set pin and no new compiled cache. This is demand scheduling, not a new raster algorithm.
4. Staging uses the same configured actual GPU targets, compact raster job, device grid, mask helper and shared isolation predicate as canonical/Direct. The transient root's staged job records actual Direct consumption. Unchanged common Direct/damage leaves remain the fast path. Staging includes permanent/presentation masks and opacity; only a complete staged frame reaches the provider. Separate original null-cache/null-prepared reference stays independent.
5. All body metrics/compiler/path/group advances and staged coverage share one existing frame PreparationAllowance, <=32 source inputs per advance, existing maxGroups. Allocation denial retains cursor/current job and dirty retry; permanent structural constraints reject distinctly. No final-target write, present or visible receipt on Pending. Presentation-basis changes discard device staging but preserve valid in-flight world preparation.
6. Default 32/96 MiB, 8 MiB/512 entries and work/AA/GPU policy remain unchanged. Reclaim only optional unused geometry/source indexes and existing optional renderer resources on actual denial; held jobs/bodies keep charged leases. Metrics distinguish full builds, first-allocation validation and checkpoint replay.

RED: immutable independently reviewed final projectRuntimeScene probe, especially 7199 long body first +512 different 64-knot bodies (default and one-step). New regression must prove bounded work and actual consumption, not merely assert readiness after an arbitrary 256-frame cap.

Native qualification adds >512 different allocations/equal bodies, distinct bodies, small one-step actual canonical/Direct, budget pressure, masks/transforms/pixels and last-release. All original 47 native/36 Node/17 Python/120 boundary checks remain. New matching normal/qualification SDK, new port >=4287; only the two repair workers after full freeze, history52/2004 and unchanged8370 cap. No commit/push/UR1d/UR2.

Resolved verification details: the existing private prepare() entry point also performs cooperative body admission using its one shared allowance; callers cannot yield indefinitely on an unqualified miss. In-use jobs shrink their admitted CPU lease in place, preserving the initial allowance under later critical pressure. Retained-ink consumers receive the qualified held body rather than reentering synchronous get on a lost alias. Creation presentation uses the existing helper and its original non-ink / creation / ink order in staging, with charged retained presentation metadata. Native fixtures use actual reachable creation state separately from erase state. Independent native geometry boundary follows the original ab7a1a3 two-device-pixel per-primitive rule; no tolerance expansion.
