# Windows public Facade and platform diagnostics — intermediate result

Windows Minimal Host now borrows the same public RuntimeFacade as the Composition and gives the Windows adapter to Debug UI as its PlatformDiagnostics provider. The prior MinimalRuntimeFacade remains for other consumers, but its ordinary control calls now use the public Facade. Surface diagnostic values come from the real existing owner. The adapter reports the existing values and does not claim screen scanout.

The initial SDKWindowsPublicAdapter test failed because the adapter did not provide PlatformDiagnostics; this RED is preserved. After the change, Windows UI-on build and 11 named native tests passed, including text ingress, touch, mouse, selection, preview origin and adapter; UI-off build and adapter test passed. A separate real DebugSnapshotAssembler test with the adapter and public Facade passed. The installed external Win32 consumer built and ran its diagnostics, resize, loss/recovery and font checks. See raw for exact commands and exits. Synthetic inputs and provider Present are not physical touch/IME or scanout acceptance.

Sources were dirty at test time and are bound by manifest hashes and the enclosing commit. The final debug UI test was added after the larger 11-test run; product source was unchanged. Remaining private Windows core paths include surface metrics/input logging, frame fallback and IME coordinate conversion. Web still lacks an independently installed platform adapter and outside-repository browser consumer. Full SDK, release, Gate and PHYS PASS are not claimed.
