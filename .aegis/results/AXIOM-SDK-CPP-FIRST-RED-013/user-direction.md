# Axiom SDK C++ 优先接入调整

本补充是用户对 API／SDK 实施方向的最新指示。它修订 [API／SDK 多平台实施方案 v0.2](<D:/axreview/sdk-20261029/Axiom API SDK Multiplatform Implementation Plan v0.2.md>) 中将完整稳定 C ABI 提前作为前置交付的建议；执行会话应对照当前 repo-local 合同和 Authority 核实冲突并修订受影响的任务包。

当前优先完成 C++ Runtime 公共接入边界和实际消费者验证。保持一个 Runtime 和编辑 owner；Product Shell、平台适配器与可选 Debug UI 应连接到同一个实例。接口应允许随产品功能演进，在此阶段明确工具链和版本匹配要求，不承诺跨编译器、跨任意版本的稳定 C++ 二进制兼容。

## 当前需要完成的工作

1. 收拢 Runtime Composition、Facade、Document、资源、产品状态和多选接口；普通使用者不依赖内部 Editor、Scene、Skia 实现，也不直接调用内部多选 port。
2. 保留现有选择、权限未知时拒绝、完整对象身份、目标/代际、回执、逐对象样式、History、资源和帧反馈行为；不以封装接口为由新建第二份选择或 Document 真相。
3. 复用现有 Windows/Web 平台资源与输入、IME、线程和帧反馈适配。共享 Runtime 管理交互和帧策略，平台承担原生资源、执行上下文和真实反馈；产品 Host 不自行决定 Preview 退休。
4. 提供必要的 C++ 安装目标、公开头和最小仓库外消费者。按阶段验证实际链接和编辑/读回/关闭，以及已纳入当前包的 Windows/Web 真实交互。Debug UI 可选，开启时必须接入同一实例。
5. Web 使用现有或改进后的必要 bridge/绑定；Android JNI 与 Apple Objective-C++／Swift 绑定按对应平台阶段引入。可以保留为连接语言运行时所需的少量 C 风格入口，但不将其自动提升为完整稳定 C ABI 承诺。

## C ABI 的处理

现有 `docs/api/canvas_runtime_api_v1.h`、其 manifest 和适用 Authority 保留；它们的声明、接受状态与实现状态必须分别核对。完整公开 C ABI 暂不作为当前 SDK 核心实施和验收的前置目标。未来若需要跨语言、跨编译器或长期独立升级的二进制合同，再单独设计、授权和版本化相应范围。

如果当前冻结执行包、验证合同或 Authority 明确要求完整 C ABI，不能通过跳过测试、伪造通过或私自修改旧包绕过；明确列出冲突，保留有效工作，以用户的最新方向修订对应控制材料。此前尝试真实链接缺少 C 符号是对旧目标的有效基线，不作为 C++ 优先目标必须补齐全部符号的证明。

## 验证与结果

执行者对当前代码和任务状态先做增量核对，沿真实调用链复用已完成成果。新入口必须经同一 Runtime 完成真实编辑、回执和读回；公开 C++ 头及安装依赖通过仓库外消费者验证。跨平台语言桥和真机验证分别如实记录，未观察项目保持 `PHYSICAL_PENDING`。

继续遵守仓库锁定的 Semantic 和 Skia 预编译依赖政策。保留 D07 未解决的故障注入及其他真实限制，不能把本次接口收口当作它们已经通过。
