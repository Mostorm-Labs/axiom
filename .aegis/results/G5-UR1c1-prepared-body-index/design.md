# Resolved UR1c1 implementation design

Existing ownership: SkiaRenderer assembles the current budget and SourceRetentionPool. Navigation tiles and retained ink currently create separate PreparedGeometryCache instances, which repeat preparation. Migrate the existing service to a renderer-held shared pointer and inject it into those current consumers. Consumers release only their own geometry/pixel references. Renderer reset/budget-owner replacement clears the shared cache; held geometry/source leases keep the old budget alive. Standalone internal navigation compatibility callers may retain their existing local service when no renderer service is supplied; no new production owner.

Prepared body index: retain unique prepared bodies independently of ObjectId. Proven immutable identity is (strong shared ownership/control block, aliased pointee, command/type discriminator); it precedes source-footprint/hash/equality work. Bounded remembered aliases refer weakly to body entries while strongly retaining and charging their actual source allocations, so they prevent ABA without adding hidden geometry use_count pins. Different immutable allocations use a fingerprint only to find candidates, then complete existing ReferenceCommand equality before sharing. A changed command forks even with the same ObjectId/digest/length. Transform, masks, viewport and object-local pixels stay outside the body key and are still validated by their existing owners.

Body entries/fingerprint nodes and aliases are bounded by current maxEntries and charged under existing Recorded quota, including explicit conservative metadata reservation. Statistics label reservation/accounting bytes, not alleged allocator RSS/copy bytes. Cold fingerprint work counts bytes actually hashed; equality counters count actual comparison invocations, not invented scanned bytes. Known identity performs no new full hash/equality/source-footprint evaluation. No extra content scan is added to obtain counters.

Source-retention index: lookup immutable owner/pointee/type first. Unknown typed/aliased views still execute the existing full footprint admission, not trusting owner address alone. Proven repeated views reuse the known bound. Retention metadata is charged and removed on last live retention release; owner changes preserve old in-flight leases. Complete source allocation accounting remains separate from shared body geometry.

Shared replayOutput remains owner-thread scratch; no threads, parallel replay, public API, new source/body IDs or semantic state. Existing per-entry/primitive/32-96MiB bounds remain. Do not add synchronous whole-history preparation to ordinary canonical/Direct leaves; those are explicit UR1c2. UR2 remains quarantined.

RED: actual old get calls on 7199-knot source,1/8/16/32shared aliases and distinct equal allocations,48warm queries each. Observe old SourceRetentionPool work and content comparisons; a warm prepared identity must not re-enter retention/full-content work. Preserve old timings and component counters, then prove new mechanism and actual renderer navigation->retained-ink pixels/usage. Also test full-content collisions/forks, aliases, quota/LRU/held lifetime and default/critical replay boundaries.

All U1C1-01..07 map to native mechanism/renderer/lifetime tests, existing regressions, and exactly two matched normal/qualification S0/S2 functional workers (canonical,drag/cancel,settledsingleerase/navigation). No extra seed, speedA/B, semantic/AA/budget changes or commit/push. Unresolved semantic decisions: none; authority/verification/scope conflicts: none.

Pressure refinement verified by additional native REDs:1024 is not a source-count cap; each live source owner/view index node is positively charged before insertion, and last release removes its weak index node immediately. Source cardinality is bounded by the unchanged actual quota. Prepared aliases are independently LRU-reclaimable on a real quota denial, even while geometry is pinned by another consumer. Invalid unknown alias/type/footprint rejection is not retried as memory pressure. Body discoverability can retire at maxEntries while in-flight data retains its own leases; fixed first body/index reservations stay pinned with that in-flight body, and later aliases never accumulate in its ownership.
