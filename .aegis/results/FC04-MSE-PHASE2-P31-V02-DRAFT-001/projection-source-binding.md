# Phase 2: source-bound projection and command path proposal

Status: PROPOSED_FOR_CONTROL_REVIEW. Subject: `6bcf2d4bbf3314e5252951190c3c475403f52665`. This is not product implementation, an ABI acceptance, or P32 authorization. The original v0.1 and v0.2 packages and existing evidence remain immutable.

## Existing boundary, and why the old binding is incomplete

`CanvasEditingRuntime` owns selection, document and D07 explicit Intent. `CanvasRuntimeFacade::Binding::apply` rejects the selected appearance/transform/lock/visible controls for multiple roots. The current selection summary exposes exactly three aggregate slots (visible, locked, opacity) and no typed per-root reasons. `CanvasControlRequest` carries no general FieldId/PropertyValue edit, so its existing payload cannot faithfully express all eight required rows; in particular blend mode and connector decorations have no corresponding general payload. `CanvasControlReceipt` has no typed changed/skipped root report. Neither generic `detail` nor an unrelated payload may be repurposed as a hidden wire protocol.

`DebugSnapshotAssembler::capture` verifies a Runtime identity and selection/semantic stamp around its existing read; `DebugControlRouter::canSubmitSelection` compares selection, semantic and Scene stamps. `CanvasControlService` captures selection snapshots at enqueue but its current dequeue check does not compare semantic generation. Checking enqueue/dequeue alone is insufficient: a displayed projection also needs a stamp checked when the user requests an edit. Windows constructs `DebugControllerContext` in `apps/minimal_runtime_host/windows_main.cpp` around `MinimalRuntimeFacade`; Web constructs it in `apps/axiom_canvas_demo/platform/web/web_debug_ui.inl` around `RuntimeComposition::controlFacade()`. Both must reach the same composition owner, with no UI kind-based semantic decisions.

ADR-0022 states that the stable product boundary is the C ABI. `canvas_debug_ui` is a static CMake library, but its include directory is PUBLIC. This supports investigating a separately rebuilt internal C++ adapter; it does **not** by itself establish that changing `DebugControllerContext`, `DebugController` layout, or an exported debug C++ header satisfies every applicable public ABI rule. No existing C ABI, `RuntimeFacade` vtable, `SelectionSummary`, `CanvasControlRequest`, or `CanvasControlReceipt` layout may be changed under the old scope.

## Concrete candidate for independent design review

1. An internal feature port owned by `RuntimeComposition`, backed by `CanvasEditingRuntime`, supplies an immutable `Projection` and a typed `Outcome`. It must be a separately named debug-only C++ interface, not a new `RuntimeFacade` virtual method, public C ABI symbol, canonical store, global registry, or pseudo-protocol in `detail`. The exact header boundary and whether a context-field change is permitted need an explicit decision. If the Debug UI context layout is considered public ABI, this candidate must not proceed unchanged.
2. Projection is computed by the existing Runtime/Selection owners on their owner thread. It carries target/runtime lifetime, document/semantic generation, selection revision, Scene generation/revision, normalized root IDs and per-property typed eligibility/reasons. A value is uniform/mixed independently of partial eligibility; unknown or failed provider is unavailable. Capture returns unavailable on lifecycle, allocation or coherence failure; a bounded retry may produce a fresh coherent read, never a mix of generations.
3. Debug UI obtains that immutable projection through one composition-injected borrowed port in **both** hosts. The port outlives the controller; controller is destroyed/detached before its composition, and no pointer is retained across composition shutdown/rebind. `snapshot_assembler.cpp` captures it between identity reads and rejects stamp mismatch; `control_router.cpp` carries the displayed projection token through submission. The panel renders eligible/total and reason codes; it does not inspect object records or construct semantic mutations.
4. Each submitted request contains client/request identity, target lifetime, displayed projection token, property identity, typed value and the explicitly confirmed eligible cohort. The existing `CanvasControlPayload` cannot hold all of these; add a private typed work item to the existing composition-owned command queue, with bounded capacity, duplicate/deadline and close semantics consistent with the current service. Do not add a parallel owner or infer a group from adjacent calls. Exact ownership between `runtime/control/src/canvas_control_service.cpp` and the composition bridge must be frozen; the existing public queue structs remain unchanged. Queue admission checks the displayed token, and dequeue rechecks target, selection, semantic/document and Scene publication, then revalidates eligibility, lock, permission, values and payload. An explicit refresh/reconfirmation is needed if the displayed cohort changed.
5. For supported rows the Interaction owner prepares the existing typed operations and calls the existing `beginExplicitIntent` / `prepareExplicitIntent` / `commitExplicitIntent` sequence, aborting on every failure. This must reserve canonical, Scene, History, and the outcome storage before publication; no fake compensating transactions. Changed/skipped root IDs and semantic reasons are produced by the owner from the committed plan in a bounded typed receipt keyed by the request identity; rejection reports zero changes. UI polls the port and never synthesizes per-target success. Expiry, duplicate request, shutdown, selection changes and receipt eviction must have explicit outcomes and tests.
6. Visible 1, Locked 2, Opacity 3, BlendMode 4, FillStyle 0x100, StrokeStyle 0x101, ConnectorStartDecoration 0x200 and ConnectorEndDecoration 0x201 retain their existing FieldId, value type and registry applicability. The bridge must carry an actual typed `PropertyValue`; it must not map distinct semantic colors or decorations to an approximate `CanvasAppearance`. Implement a property only after independently verifying its existing reader, validator, exact preimage and inverse. A missing row stays unavailable with reason and blocks scope completion where required; do not claim all eight rows are done by enumerating IDs.
