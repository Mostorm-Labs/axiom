# External Web input and initial resources — scoped result

The external Web consumer uses installed Runtime interfaces and an application-owned text bridge/carrier copied from the existing Demo; the runner requires exact byte parity. The external build uses the accepted local core nlohmann/json and locked Semantic and Skia SDKs. It now has an interactive Ink/Text mode; Chrome CDP exercised synthetic pointer and composition start/update/result, single confirmation, Enter and return to Ink. Actual OS IME, candidates and touch remain PHYSICAL_PENDING. Full commands and the red-to-green browser observations are in raw/external-ime-*.json.

A startup-only, empty-document resource metadata binding plus full binding token and verified resource-byte submission/receipt use the existing Runtime owner. The native test exercises invalid metadata, retry, one-shot binding, hash mismatch, stale token, wrong thread, close and nonempty-document rejection. Windows/Web installed external consumers exercised resource-token access. This is not document save, restore, synchronization or a persistence guarantee.

The old Web Fit/tool and fractional Sticky tests clicked stale coordinates after the selection controls added a row. The fixed tests click actual controls and assert the real tool state, Fit, four Sticky cases and Undo/Redo. They pass against the current source. Their former failures and exact baseline remain in STEP-009. Native targeted CTest passed 13/13; see raw logs and manifest hashes.

The Runtime still does not expose a complete document identity/restore, local-operation delivery/close fence, storage durability or remote-sync public lifecycle. Existing DataBridge/close material is proposed; it would be unsafe to claim these capabilities from SnapshotCodec alone. D07 Protobuf/Abseil OOM remains unchanged. No SDK release, Gate or physical acceptance is claimed.

A red test showed a manifest could be initialized during an active pointer before any object existed. The final implementation rejects initial binding after interaction has started and while text editing is active; the final Windows matrix includes this regression. The existing Section snapshot rejection test ran and passed as a negative test: this confirms that Section snapshots cannot currently be encoded, not that document persistence works. The user accepted the boundary in which the SDK exposes document/operation channels while the application or data layer owns storage and network.
