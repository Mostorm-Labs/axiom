# Execution, oracle and closure contract

## Scope and stage
This stage defines the completion target; it does not implement production oracles/harnesses or grant P32. The proposed gate is FC08-DEV-AUTOMATED. Physical Windows/Web observations stay deferred to FC13, preserving PX0 and previous task identities. P20 closure must accept the bounded obligations before P31 freezes them. A future reviewer must not add redundant tests solely for more confidence.

## Observation vector
For each canonical mutation observe exact sorted records including Placement/Transform/Content/PropertyBag, manifest, parent/index views, SemanticGeneration, canonical commit ordinal, OperationId ledger effect, History entries/cursor/redo tail, receipt canonical/projection axes and local selection/scope. For zero-commit failures the canonical vector and History are unchanged; diagnostics, queue records and uncommitted allocator gaps may differ. Successful Undo restores touched document state, not monotonic generation/ledger.
Scene observations additionally identify published semantic generation, SceneRevision, draw/bounds/index/damage basis and preview session/revision. Read all observable publication boundaries with a deterministic scheduler, not just the final screenshot. Test-only observers may observe state but cannot implement the missing production semantics or alter the outcome.

## Independent oracle families
E01: use exact accepted IDL/tag manifest plus hand-authored SectionContent wire samples; compile source-complete successor descriptor and compare assigned messages to an independent table. Complete envelope/snapshot vectors must be authored with inherited fields under a reference writer, not recorded from DUT. Model canonicalization and malformed wire acceptance are different checks.
E02: literal object tables and an independent flat-map/parent-graph checker. Production Engine/Codec/normalizer/OrderKey allocator/Scene compiler must not be reused to decide expected poststate. Existing reference/indexed parity is useful for storage but not sufficient semantic independence.
E03: construct real F/U under the candidate, export actual bytes/typed values, meter them independently and compare exact snapshots at injected precommit checkpoints. Short forward Delete uses complete inverse closure. Replay remains independent of local History capacity.
E04: hand dyadic literals plus independently ordered IEEE binary64 reference (ties-to-even each operation, no FMA, no hidden extended intermediate). Use only the accepted P12 threshold; new tolerances are not a P20 choice. Non-dyadic results require reference hex components before production mutation.
E05: fixed polygons, actual geometry and authored selected IDs. Concave containment must inspect the region, not four corners or AABB only. Keep old FC01A set algebra and Group scope unchanged.
E06: compare literal geometry/damage/draw expectations at actual Scene publication; separate canonical and projection failure. Full-rebuild-versus-incremental equality is corroborative when it shares the same compiler/oracle. Font refresh must not create canonical writes.
E07: controlled event schedules and exported observations against hand-authored allowed/forbidden traces. Check every visible handoff; end-state-only tests are inadequate. A synthesized bad trace demonstrates oracle sensitivity, not a claim that old Axiom executed that trace.
E08: exercise same mounted owner with source, request, target, selection and pointer identities and fault schedule. Use public receipts plus independent store/history observations; never substitute UI-disabled state for actual rejection.
E09: fixed version/capability truth table and independent canonical input framing. Never derive malformed expected capability order from production push_back output. Old binary/capability-limited reader must reject unknowns before publishing Ready; a downgraded capability flag alone is not proof of old binary compatibility.
E10: build ordinary public consumer and actual native/WASM bridge adapters. Run all platform-neutral applicable E01-E09 cases on Windows and Web where the declared execution profile requires them; these runs check realization/rounding/bridge parity, not independent oracle duplication. Compare both to the independent expectation. Browser adapter tests need actual browser/WASM execution, not only Node stubs.

## Exact execution contract to bind at P31
Logical executable interface: <FC08_RUNNER> --design <manifest.json> --case <case_id|all> --profile <windows-native|web-wasm|headless> --output <run_dir>. This is a REQUIRED INTERFACE CONTRACT, not an existing executable or command claimed to have run.
P31 must bind the real runner path/sha, build configure/build invocation, target lists, browser/native runtime version, ABI and test discovery list. Equivalent test frameworks are allowed only if the exact case and variant mapping and outputs are retained. No literal guessed CMake target is asserted to exist.
Execution sequence: (1) validate accepted source/verification identities, (2) configure/build required native and Web profiles, (3) enumerate nonempty cases and variants, (4) execute baseline RED applicability probes, (5) run each materialized case with raw observations, (6) run bound inherited regressions, (7) produce per-case result records, (8) check all required cases present and matching. Any compiler/runtime environment failure is BLOCKED_ENVIRONMENT, never semantic RED or PASS.
Thresholds: zero canonical mismatches, zero forbidden intermediate publications, zero missing successful positive capabilities, zero failed required fixture/variant. Fixed-seed extra fuzz, repeated CI/local execution, screenshots duplicating automated geometry, performance p50/p95, proof-of-proof tooling and extra provenance are corroborative, not separate mandatory artifacts. No invented millisecond, FPS or memory SLA beyond existing explicit protocol/admission budgets.

## RED protocol
R01 feature-absence RED: feed an independently valid accepted Section/1 and opcode17/18 message through the available old codec/ingress. The baseline is expected not to satisfy the new positive contract; record actual unknown/unsupported result. A compile error or malformed fixture is NOT a valid RED. If an authorized actual baseline already supports it, record the verified applicability change rather than demand a fake failure.
R02 critical temporal oracle controls: the fixed C01 bad trace ending correctly after an x30 intermediate and C02 late wrapper reselection MUST be rejected by the trace oracle. This is a narrow sensitivity check attached to E07, not a new product defect claim or an extra evidence family.
R03 behavioral predecessor RED: when the actual bound baseline has executable FC08 behavior and a documented counterexample, run that exact case before its production repair. If known-unsatisfied behavior passes, classify VERIFICATION_DESIGN_DEFECT. When feature absent, do not call all temporal behaviors baseline RED; record unavailable and prove them after implementation with the same fixed expected cases.
Do not rewrite expected cases after seeing production results. Correcting a faulty fixture/oracle requires explicit P20 delta review, not silent golden recording. No requirement to construct an endless chain of tests for the generator/validator.

## Materialization prerequisites (not unspecified product decisions)
M01 bind actual source-complete inherited baseline and BASE-01 descriptor alignment, preserving historical lock and exact FC08 assignments.
M02 materialize full typed/wire Operation/Snapshot and non-dyadic numeric reference values, including all listed variants, with reviewed input hashes before production implementation. The six single-message wire samples in this package are not the full corpus.
M03 supply independent expectation/reference implementation and test adapters; do not let production populate expected files. Bind actual logical error-category mapping rather than inventing new numeric protocol errors.
M04 bind concrete execution profiles, tests, build/toolchain/browser and deterministic checkpoint access. Platform physical observations remain deferred, not quietly omitted.
M05 run a targeted P20 closure/control review of blocking necessity, expectation correctness, RED applicability and source binding. Until M01-M04 are mechanically bound, do not call this package an executable P31 lock. P31 may materialize the smallest accepted control/evidence contract; it may not invent missing acceptance meaning.
