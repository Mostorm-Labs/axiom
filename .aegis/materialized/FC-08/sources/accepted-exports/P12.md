## 2. 对象身份和 Schema 所有权

候选身份为 <code>ObjectKind Section = 10 / kind_version = 1 / ObjectContent.section tag = 12</code>。这些是待 P21/P23 核准的分配请求，不是已占用的正式编号。ObjectContent tags 10/11 已属于 Brush 分支，禁止复用。Group 保持其已接受身份和空 GroupContent；不创建 Frame。

Section 仍使用既有 ObjectRecord：ObjectId、kind/version、Placement、Transform2D、PropertyBag、ObjectContent。Section 的 erase\_masks 必须为空；不能作为画笔局部擦除载体。

<code>boundary</code>、title、padding、header\_height 由 SectionContent 拥有；背景色与自身透明度由适用 PropertyBag 字段拥有。不要在两个位置重复保存同一属性。Selection、scope、hover、handles、派生 world bounds、子节点索引和渲染缓存不进入 ObjectRecord。

## 3. SectionContent/1 可执行字段候选

```txt
SectionContentV1
  boundary      : Rect2          // candidate message tag 1
  title         : UTF8 string    // candidate tag 2
  padding       : f64            // candidate tag 3
  header_height : f64            // candidate tag 4
```

| 字段 | Presence / 合法值 | 默认与修改语义 |
| --- | --- | --- |
| boundary | 消息及 x、y、width、height 均显式存在；f64 finite；width、height 严格正；x、y 可为负；边界端点运算不得溢出 | 无缺省几何；创建方物化实际数值。整体替换，禁止同时再保存 width/height 第二份真相 |
| title | 显式存在；允许空串；有效 UTF-8；上限沿用 generic\_utf8\_string\_bytes=1,048,576 | 空串是合法值，不等同于缺失；保持 Unicode 标量序列，不擅自 trim、NFC 或更换大小写 |
| padding | 显式存在；finite 且不小于 0 | 0 合法；创建 preset 解析后写入。仅用于显式 Wrap/Fit-to-content 的边界计算，不引入持续自动布局 |
| header\_height | 显式存在；finite 且不小于 0 | 0 合法；标题带位于 boundary 内，显示高度为 min(header\_height,boundary.height)，不挤压、移动子对象 |

所有负零按既有规则规范化为正零；NaN、Infinity 拒绝；不 clamp 非法值。显式默认值是否省略必须有既有或新增 Authority；本提案对以上必需字段不做缺省省略。不存在独立 SetField/Clear(title) 的双路径：将 title 设为空串通过同一内容操作表达。

宽高、padding、header 的协议上限不凭空设置某个画板像素数：采用 finite/domain 约束和现有编码、解码预算；产品 soft limit 可更严格但不是新 wire 规则。<code>x+width</code>、<code>y+height</code> 及实际计算中出现非有限结果时，构造方不得提交伪造修复值。

标题是 Section 元数据，不是新的 RichText child。标题 glyph、字体测量及截断属于呈现；不得依赖平台字体宽度反写 boundary。标题/标题带保持在 boundary 内；只约束标题自身呈现，绝不裁剪 Section 后代。

### 3.1 外观字段的明确选择

本版选择沿用 <code>fillStyle (0x100)</code> 和 <code>opacity (0x3)</code>，以 successor applicability 增加 Section；分别复用 FillStyleValue.None 和 opacity=1 的协议默认，以及既有 Clear=删除 entry、显式默认归一省略规则。创建时非默认背景必须显式物化，主题不能改变历史文档值。

opacity 仅作用于 Section 自身绘制，不作用于后代，不新增 subtree compositing。V1 <b>不新增可编辑 Section strokeStyle、blendMode、title-style</b>；未被产品批准的边线编辑不因底层字段可复用而自动进入范围。边界命中和选中 chrome 是单独的交互呈现，不冒充文档 strokeStyle。

Section/1 不接受 visible、locked、connector decorations 或未知 FieldId 的 Set/Clear；这明确实现本轮 V1 不提供 Section 级 lock/visibility 的边界。子对象已有的属性值不变。Section 位于某个 Group 下时，仍遵守既有 Group 的有效可见性/编辑资格规则；不是绕过祖先规则的新特权。

### 3.2 预算

沿用已观察到的 V1 安全预算：Operation 33,554,432 bytes、单 ObjectRecord 16,777,216 bytes、generic keyed batch 65,535 项、OrderKey 1～32 bytes。新增嵌套数组和 guards 计入总编码预算，先检查长度再分配；禁止按部分批次提交来绕过单意图原子性。

## 4. 层级、引用与选择边界

| 父节点 | 允许的直接孩子 | 不变量 |
| --- | --- | --- |
| Document root | 全部基线已接受 kind/version，加 Section/1 | root 是空 parent\_id，不发明 Page 对象 |
| Group | 全部基线已接受 kind/version，加 Section/1 | 零个或多个；GroupContent 不增加 children/bounds |
| Section/1 | 全部基线已接受 kind/version，含 Group、Section/1 | 零个或多个；允许交替嵌套 |
| Sticky | 仅零或一个直接 RichText child | 原有基数约束、文本身份不变 |
| 其他现行 leaf | 不允许成为非 root 父节点 | 不能用 schema 扩展暗增容器能力 |

全结果图必须是单父、无环、引用存在的森林。拓扑校验使用 staged final graph，不依据 payload 输入顺序。跨父重设不能通过单个局部检查看漏环。

Section/1 与 Group 在本扩展中均不成为新的 Connector attachment target。Connectable 继续按已接受的 Shape/Image/Sticky 及其后续版本规则查询，不能回退 Shape/2、Shape/3。Section 内外对象可保持 Connector 关系；AttachedEndpoint 不决定 Placement。安全移除容器不会删除保留的 endpoint target；破坏性 Delete 继续使用现有 subtree + Connector fixed-point cascade。

SelectionScope 仍只有 Group 的显式编辑边界；Section 的结构层级不等于新的 editor scope。本文不改变 FC-01A 的 intersection、Shift-add、取消和 hidden/locked 规则；全包含 Section 的判断使用实际变换后的 boundary，而不是未变换 AABB。标题带在 boundary 内，不扩张一个额外 canonical 选择对象。

## 5. 一般仿射、独立边界与变换闭包

列向量约定不变：<code>W(o)=W(parent(o))*L(o)</code>。Section 的记录不能限制为纯平移。一般矩阵合法性沿用已接受 Transform2D leaf 约束；Section 不另设更窄的旋转/剪切白名单。需要求逆的命令遇到奇异、溢出或不能安全构造的数值时拒绝该命令，而不是改写历史对象。

<b>Group Move/Rotate/Scale：</b> 修改所选 Group 根的 L 一次；所有结构后代通过组合受影响，包含隐藏成员，不能只修改当前可见者。后代自己的 L、样式和内容不改。多个根形成无祖孙重复集合。

<b>Section Move：</b> 同样修改根 L；boundary 保持局部值，后代随容器坐标系移动。

<b>Section Resize：</b> 只替换 boundary。L、所有后代 L、Placement 和内容保持原值。负 boundary.x/y 是允许的，不把局部坐标系重置到新左上角。

<b>Reparent / Wrap / Unwrap：</b> 保存目标根的旧世界矩阵 W\_old；在最终目标父坐标中求 <code>L_after=inverse(W_new_parent)*W_old</code>。若新父是本次创建的包装容器，按最终图拓扑顺序求其 W；若移除多个嵌套容器，只重设存活 frontier 根，绝不对所有后代再重复补偿。

<b>反例修复：</b> Group 的世界矩阵为旋转 90°再缩放 2 倍，Section 的 L 为 I。Ungroup 后 Section 的 L 应承载原 Group 的矩阵，不能被 pure-translation validator 拒绝。

<b>边界示例：</b> boundary 从 <code>(0,0,100,80)</code> 改为 <code>(-20,0,120,80)</code>；child 的 <code>(30,20)</code> 不变。即使 Section 的 W 带旋转/缩放，子对象世界位置仍由同一 W 和 L 得到，不产生额外 transform 操作。

## 6. 数值和确定性：不把协议语义交给 P20

### 6.1 Canonical 层

序列化、precondition equality、History 精确恢复采用既有规范化规则后的确切值/规范字节。<b>没有 epsilon-equal ObjectRecord，没有 approximately-equal OperationId payload。</b> 新拓扑操作提交的是完整绝对 Placement/Transform 结果，不在 replay 时重新求逆、重新读取 UI bounds 或重新分配 OrderKey。

P13 的 wire 接受谓词是类型、finite/domain、明确 preimage、最终拓扑/引用及预算约束。它不再包含 v0.1 所谓“按 P20 tolerance 判断 world-pose 是否相等”。姿态保持是下面的命令构造契约；它与既有 SetTransforms 一样，不能通过 UI 意图或几何近似暗改 canonical equality。

### 6.2 PoseConstruction/1 候选规则

为本扩展的 PreserveWorld 命令构造固定计算约定：binary64、每个基本乘加减除按 round-to-nearest/ties-to-even 舍入；不用 FMA、扩展精度中间值、平台相关 epsilon 或分解再组合矩阵。矩阵布局、乘法项顺序、inverse 公式沿用 Geometry Types 的列向量定义；乘法每个双乘积之和先左项、再右项，平移再加父平移。输出规范化负零。

新父路径从 root 到 parent 按序组合；每个旧 W 从同一个 coherent read 捕获。非有限中间值或 inverse 不可构造时，返回 NumericRange/UnsupportedPose，不提交，也不偷偷把对象扁平化到 root。

构造质量预算在此提出，不留给 P20 决定：对每个迁移根的 coherent conservative subtree-local geometry bounds 的四个角点，逐坐标比较构造前后 world 值，要求 <code>abs(after-before) <= 2^-32 DU + 2^-47 * max(1 DU,abs(before),abs(after))</code>。没有可见几何的空 Group 使用局部原点与两单位基点；有隐藏成员时 bounds 必须覆盖结构成员，不能仅使用 viewport visible subset。缺少可信几何边界时不伪称姿态验证成功，命令返回明确能力原因。

该预算是 PreserveWorld 命令的数值质量上限，不是 codec 接受域，不随 zoom/DPR 改变。Replay 只写已验证的绝对结果；不再次执行该质量检查。P20 应独立用数学/手工几何 reference 验证构造规则和阈值边界，而非从被测实现生成期望。

History 恢复保存的原始规范 Placement、Transform、Content 和 OrderKey，不反复求逆；因此撤销的目标是精确前态，不累积矩阵漂移。资源/Scene 像素完全相等不是本字段合同凭空保证的事实。

### 7.1 分配请求，不是正式 Registry

| 命名空间 | v0.2 候选 | 保留约束 |
| --- | --- | --- |
| ObjectKind | Section=10，kind\_version=1 | 已有 kind IDs 与全部已接受 version pairs 不变 |
| ObjectContent oneof | section=12 | 1～11 保留；10/11 不是 Section 编号 |
| OperationKind / payload oneof | SetSectionContent=17；EditContainerTopology=18 | 1～16 不复用；16 已为 UpdateResourceManifest。v0.1 的四个符号从未发布，不需要协议迁移 |
| Operation envelope | schema\_version=1；这两个新操作 payload\_version=1 | 不改已接受旧操作版本矩阵；未知新 opcode/variant 拒绝 |

正式分配前必须核对现行 Registry successor、descriptor reservations、Authority materializations 和 golden profile。不能仅看到某一文件最大值就宣布已获得编号。

### 7.2 Snapshot / 操作日志 / 写入参与者分开判定

提议新 capability <code>section-v1</code> 覆盖 Section/1 的字段、层级、外观适用性和内容编辑；<code>container-topology-v1</code> 覆盖 P13 的有界拓扑操作。这些名称亦待 P23 发布。

| 输入 / 行为 | 新 reader/writer | 无相应能力的旧 reader/writer |
| --- | --- | --- |
| 合法旧 Snapshot 1/2/3，无 Section | 按原版本/能力矩阵接受；不自动升级或改 bytes | 原行为不变 |
| Snapshot 1/2 含 Section | 拒绝，不能把新字段偷放进旧 profile | 拒绝，不丢弃 Section 后部分加载 |
| Snapshot 3 含 Section | 必须同时满足原 manifest/frontier/digest 条件和 section-v1；所有对象 staged 后原子 bootstrap | 在未知 kind/branch/capability 处 fail closed，不报告 READY |
| Snapshot 3 有 Section 但缺 section-v1 | 拒绝；重新计算 content-derived required capabilities，不能信任载荷遗漏声明 | 不得通过忽略 capability 获得写入资格 |
| Group-only Snapshot，但后续 journal 含 EditContainerTopology | snapshot 仍按原状态 profile；replay 必须另具 container-topology-v1 | 不能因 snapshot 可读而跳过未知 journal 操作 |
| Section 被完整移除后的新 checkpoint | 状态能力由实际 checkpoint 重算；不把历史编辑会话塞进 ObjectRecord | 是否可继续 replay / 成为 writer 仍由对应 journal/session 能力决定 |

Snapshot3 原有 capability 编码顺序和 bytes 不改；新 profile 先生成原基线的规范 required\_ids，再于有 Section 时追加一次 <code>section-v1</code>，严格检查重复、缺失、未知项和对应 digest。没有 Section 不追加。旧文档的 canonical digest 输入不被本功能无条件改变。具体基线函数和已接受能力集合需在 P21 精确绑定，不能用源码中一份历史十五操作表代替。

操作流和写入 admission 必须检查实际新操作能力；本设计不声称已经实现 G8 协作握手。未知操作导致 replay 停止/Loading 失败，不能跳过后发布部分可编辑文档。这里定义的是要求，不是宣称所有旧二进制已经通过测试。
