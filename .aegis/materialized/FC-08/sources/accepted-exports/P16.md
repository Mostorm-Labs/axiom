## 1. 三种状态机不混用

```txt
Gesture:
  Idle -> Previewing -> CommitRequested -> Ended
                  -> Cancelled / Stale / Rejected

Command:
  Received -> Queued -> Preparing -> Admitted -> CanonicalCommitted
                               -> Rejected / Cancelled (before commit only)

Projection:
  Coherent(g) -> Preparing(g+1) -> Coherent(g+1)
                              -> RecoveryPending -> Coherent(g+1 or newer)
```

Command canonical commit 是不可回退成 Cancelled 的线性化点。本页的新容器域 receipt 以 canonicalOutcome 与 projectionOutcome 分别表达事实；其组合显示的 Applied 表示 canonical 已提交且所需投影就绪，不重新定义现有 ProductControlReceipt、ApplyDisposition 或旧入口的 Applied 含义，也不表示 GPU 已显示、保存完成或其他视图已看见。presentation/durability 不明时保持 Unknown；投影失败、延迟或后续变化不得把已提交结果改为 Rejected/Cancelled。

每个步骤标识同一个 target epoch；OwnerSequence 决定 control/terminal 输入的竞争先后。不能拿 source timestamp、SceneRevision 或 frame number 代替 canonical commit order。

## 2. F01：跨父 Wrap / GroupSelection

1. <b>Facade：</b> 接收 typed intent；复制显式 targets 和 selection token，预留终态回执位置，检查基本格式/队列容量。Queued 只表示已接收。
2. <b>Composition owner：</b> 在 safe point 验证 mount、可写性、feature admission 和当前选区身份。目标被换掉时 Stale，不读取后来新的选区替换原请求。
3. <b>Interaction planner：</b> 取得一致的 canonical S 和与 S 对应的 geometry snapshot。几何尚未就绪则不以旧 Scene 计算。Group scope 按原规则；targets 使用合法 selection roots，不展开全部后代。
4. <b>Planner：</b> 计算最近合法共同祖先、wrapper ObjectId、已接受 OrderKey slot、各 root 的绝对 local-after、Section boundary 和 presets。未来创建的 ID 不作为已提交对象提前对外公开。
5. <b>Semantic prepare：</b> 构造 IntroduceWrappers，校验完整 guards、能力、无环、引用与最终顺序，得到不可变 prepared plan。任何失败不改变 store。
6. <b>Command/History：</b> 从该 plan 的 S1 构造真实 Release inverse，校验精确 touched-state 恢复、正反向编码及集合预算，预留 History。65535→65536 成员的反向超限在这一步拒绝正向。
7. <b>Owner commit：</b> 核对 plan/read generation 绑定；一次发布 canonical、幂等和 ChangeSet，消费已预留 History record。一次意图恰好一个 History unit。在同一 owner 完成顺序中，Interaction 对发起视图执行一次已经定义的本地 selection consequence，按 §9.1 的 target/selection/scope fence 约束；不把这次选择写入委托给稍后的 Scene 回调。
8. <b>Scene coordinator：</b> 对旧父路径、新 wrapper 子树和受影响依赖准备一致 Scene/Bounds/Spatial/damage；按 P15 §8.1 在同一可观察 publication 交接点撤下对应 preview。不得先把 wrapper 的新位置画出来而保留孩子的旧世界变换，也不得在新 committed pose 上再次叠加旧 preview delta。
9. <b>Interaction/UI：</b> 从当前 per-view SelectionContext 投影 handles、toolbar anchor 和可用动作，并更新同一请求的 projection outcome；不因该旧命令的 Scene 此时才就绪而重新选择 wrapper。逻辑 selection 本身不产生 canonical Operation。receipt 分开保留 canonical 成功与 projection 进展。

Geometry/OrderKey 保真承诺沿用 P13：成员之间和非成员之间的相对次序保持，真实跨父包装不承诺所有外部 interleaving 永不改变。

## 3. F02：空 Section 创建、移除与 Undo

CreateSection 的唯一产品路径选为 IntroduceWrappers；container list 非空、adoptions 可以为空。给空对象的坐标、boundary、title、fill/opacity 预设都在 common planner 解析。

Remove 空 Section 用 ReleaseWrappers，frontier 为空，仍需原 wrapper、父级完整 children expectation。Undo 用保存的原 ObjectId/record 恢复，不分配另一个新容器。若后来有孩子加入，原 inverse 的完整成员 guard 失败，返回 HistoryConflict；不能把新孩子顺便删除或移出。

无 Scene paint 的空 Group 不伪造点击矩形；其 Object List 选择和生命周期仍用现有 typed object identity，不能让“不可在画布命中”变成“文档里不存在”。

## 4. F03：Resize Section 边界与嵌套 Group transform

Down 被现有 arbiter 接受后，Interaction 捕获 SectionContent、world/ancestor basis、camera/metrics 和 PointerKey。Move 将 view-logical 点转换到 Section local，更新 transient boundary；不更新 ObjectRecord。

例如 local boundary 从 <code>(0,0,100,80)</code> 变为 <code>(-20,0,120,80)</code>：只有边界变了，Section Transform 和所有孩子 local Transform 均不变。标题派生布局可以重算，子 Text 不因 Section 宽度变化重新 wrap。

Up 形成一个 SetSectionContent，完整 expected\_content 与所需 geometry\_basis 通过后走 E01。若祖先在手势中旋转或 reparent，不能把旧屏幕计算套到新坐标系；结束为 StalePrecondition，保留当前 canonical 状态。

Group move/rotate/scale 使用既有 SetTransforms，只改变合法 selected roots；Section 的直接移动也用该路径。Scene 按 parent 链组合 world transform 一次，并失效整个受影响子树。已经变换了祖先，不能再对每个孩子施加相同 delta。

## 5. F04：拖放、跨边界与取消

仅跨过 Section 外框不产生 membership mutation。Interaction 可读取 Scene 给出 transient drop candidate；candidate 由 common capability 与 scope 验证，不由 Host 根据画面重叠确定。

confirmed Up 且 drop 被接受：desired W 使用最后 confirmed preview，而不是起始 world pose；一次 RelocateObjects 同时完成最终移动与 parent/order/local-after。纯 MoveToContainer 则用当前 W 作为 desired W。两者都不先提交 move 再提交 parent。

Cancel／source lost／capture lost／tool switch 在 commit 前：释放 logical claim、preview、reservation，保留 canonical 文档与 History；已完成的选区遵循原取消恢复规则。迟到的 Up 因 token/generation 失效不能提交。pointer cancel 不把已经提交的命令变成撤销；需要撤销时走明确 Undo。

## 6. F05：批量嵌套 Release 与逆向恢复

R 为要移除的 wrapper 集合；frontier 仅包含 before parent 在 R 中且自身不在 R 的存活对象。planner 用完整最终图与绝对后态，不按输入顺序执行一连串 detach。

对 <code>A(移除) -> B(保留) -> C(移除) -> D(保留)</code>，frontier 为 B、D；canonical 结构补偿允许其祖孙依赖。一次 Release 完成全部提升，逆 Introduce 一次恢复 A、C 和 B、D 原 Placement/Transform/keys。UI selection antichain 不可用来拒绝这个合法 inverse。

只迁移现存 leaf 的结构字段，不用整对象 preimage 覆盖后来更新的文字/图像内容；被移除 wrapper 使用完整 record guard，保护其 title/style。原 parent 已不存在、wrapper identity 冲突、成员变化均在 commit 前拒绝，History cursor 不动。

## 7. F06：Rename、外观、Undo/Redo

普通 inspector/native text widget 保留未提交编辑草稿。确认 title 后向 Facade 发送 RenameSection，Runtime 从受控 read basis 形成 SetSectionContent；preedit、候选字和 Enter 事件不各自独立提交。与 concurrent boundary 改动冲突时 expected\_content 失败，不强行覆盖。

fill/opacity 走现有 PatchProperties，Section 不支持的 stroke/visible/locked 不得误落到 generic appearance setter。Clear/default 仍按已接受 Field Registry。

Undo/Redo 重新验证 guard 和当前所需能力，每次使用新的 OperationId，执行当前方向及其反向的 E01 准入。历史 cursor 只在 canonical 成功时移动一次；重投已执行 ID 只观察原结果。反向内存预留失败时没有半撤销，redo 分支不被提前清空。

## 8. F07：重试、背压与结束事件

| 时点/事件 | Owner 处置 | 可观察结果 |
| --- | --- | --- |
| 请求尚未入队即容量不足 | Facade 不接纳、不分配 operation | Backpressure，零写入 |
| 相同 request key+相同 payload | Facade 查询或返回原 outcome | 不创建第二个命令 |
| 相同 key 不同 payload | Facade 拒绝 | Collision |
| prepare 后内部 generation 变化 | commit owner 丢弃计划，重验原 payload/guards，并重做必要预算预留 | 不能使用旧 S1/U；语义冲突则 Stale |
| 当前同 OperationId 已成功 | Semantic ledger 在 state guards 前去重 | AlreadyApplied，不再次写入 History |
| active gesture cancel 到来 | 保留终态通路，owner invalidate session | 后续旧 Move/Up 无效 |
| 成功后 receipt 尚未被客户端看到 | 保留既有 outcome/ack 身份 | 查询原结果，不以新 requestId 盲重试 |

每个请求的 byte/entry 限额在分配前检查。Facade 对控制/终态消息背压，不能通过丢失终态或切分 canonical 批次来“保持响应”。中间 Move 的合并不会跨 session、target 或 metrics 边界。

## 9. F08：commit 前后故障域

commit 前失败：文档、索引、generation、ledger、History、canonical event 均保持前态；preview 清除或保留为明确失败态，不当成成功图像。

commit 后 Scene failure：Composition 保留 canonical 成功与 commit identity，History 已有一条记录。Scene 保留最后 coherent frame 或显式 unavailable，使用现有 recovery 从当前 committed state 重建。恢复只产生 projection revision，不新增 Operation/History。对 stale projected geometry 的写操作禁止继续基于旧图计算。

恢复至较新的 canonical generation 可以包含多个已提交变更；旧 async result 不得覆盖新 projection。没有匹配 snapshot key 的 route/title layout 不得发布。恢复成功后的 receipt/readback反映已就绪，但不重发 canonical commit。

### 9.1 ARC-CR-C02 — 本地选区后果与迟到回调

本条限定本地完成回调的写权限，不改变 Wrap 后选择新容器等已接受产品结果，也不为 Section 新增 scope。canonical 提交成功后，由 Interaction 在同一 owner 完成顺序中对发起视图执行一次产品已定义的 selection consequence，并更新其本地 revision。需要的本地状态准备不得在已发布后制造一个可被误报为 canonical 失败的新失败点。

请求携带的 target、selection/scope token 继续在提交前验证；若已失效，按原规则在写前拒绝。若 canonical 已提交，视图随后 detach、scope/selection 已被较新动作替换，任何延迟的结果处理只能保留 commit outcome 并放弃过时的本地副作用，不能改写新视图或新选区，不能把已成功操作改报 Stale/Rejected。其他视图只执行其既有的存活性/结构 reconciliation，不复制发起视图的选区。

Scene publication/recovery callback 只推进 geometry/readback/receipt 的 projection 状态；它没有重新选择原 wrapper、恢复旧 primary 或重放旧 scope 的权限。当前 SelectionContext 与可用 Scene 不匹配时，相关 handles/toolbar anchor 返回 Pending/Unavailable，而不是混用新选区与旧几何。无需为此把 selection/scope revision 写进 Operation。

设计反例：Wrap 在 g+1 提交，Scene 待恢复；用户随后通过合法本地入口选中 T；恢复至包含 g+1 的 g+2 后仍选择 T，不恢复 Wrap 当时的新 Section。若该 Section 已被之后的提交删除，旧 Wrap receipt 仍说明曾成功，当前 readback 不得复活它。一次 canonical commit 只产生一次 History 记录，恢复和回执刷新不产生新意图。

本条与 P15 §8.1 配套：旧 preview 不叠加到新 Scene，旧 completion 不覆盖新 selection。OwnerSequence、target 和必要的本地上下文 fence 共同约束，不使用墙钟时间猜测新旧。

## 10. F09：detach、close 和重新挂载

Owner 先停止新写准入，作废 target/view/attachment identity，再取消未提交 sessions/queued work、释放 reservations，移除该 view 的 preview。close 前已经线性化的 commit 继续属于文档，不能当作取消。

旧 view 的 callback/result 需同时校验 epoch 和 request/session identity；re-attach 新 view 不继承旧 pointer token。renderer surface 丢失和 Document close 是不同事实，不从 surface generation 猜文档状态。按照原 lifecycle contract 决定可写性；不增加假称持续可写的旁路。

## 11. F10：Snapshot／replay 与 persistence

Restore 先执行已接受 schema3、manifest/frontier、sorted capabilities、digest 和 typed 结构校验，再 staging 全图并一次 publication。缺 section-v1、unknown17/18 或 journal 缺 container-topology-v1 均不能部分恢复后报告 Ready。旧 legacy 读取不被升级成可无条件写入的新 writer。

Headless replay 经过同一语义验证和幂等，但不创建本地 editor History、不执行 E01 的本地容量门槛。Scene 尚无 surface 时可以保持 semantic ready 与 visual not-attached 分离。

CanonicalCommitRecord 交现有 recovery/persistence owner。Snapshot 只读 coherent committed document，排除 selection、preview、pending rename 和未提交 wrapper ID。write-to-disk/network acknowledgement 独立报告；本设计不建立 G7/G8 新日志系统。
