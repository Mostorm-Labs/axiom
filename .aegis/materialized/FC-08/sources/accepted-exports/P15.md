## 1. 模块和依赖

| 模块 | 建议归属 | 输入与输出 | 不变量 |
| --- | --- | --- | --- |
| typed container intent/readback | foundation 的 runtime public types | 拥有数据的请求、receipt、不可变 snapshot | 无 ImGui/Skia/Win32/DOM、无 mutable store |
| Container intent adapter | composition 的 CanvasRuntimeFacade | 验证 target、排队、receipt retention、owner dispatch | 与现有输入共享一个 owner；不另建 editor |
| ContainerCommandPlanner | interaction | ReadLease + 明确目标 + 指令 → 单个 canonical F 与所需前态 | 不 apply；LCA、顺序、姿态计算只在 common code |
| ContainerGestureSession | interaction | normalized pointer + captured basis → transient preview / final intent | 每次 confirmed commit 最多一个意图；Cancel 无写入 |
| Undoable command coordinator | interaction + composition commit seam | F、S/S1、真实 U、预算和 reservation → owner-bound ticket | E01 由这一处执行；不是新 History owner |
| container operation validation/prepare | semantic 内现有 OperationEngine | 已接受17/18 → staged graph / apply plan / rejection | 所有入口使用同一规则，headless 不依赖 UI |
| container derived geometry/query | scene + common geometry | 同版本记录 → world geometry、三种 bounds、query candidates | 后代 overflow、不重复变换、不另建成员真相 |
| title presentation adapter | scene/text | plain title + header rect + existing font resources → derived glyph layout | 不创建 canonical RichText child，不反写尺寸 |

建议的新增头文件为 <code>canvas/runtime/container_input.hpp</code>；具体文件拆分与内部类名可在授权实施时等价调整，以上 owner 和接口不变量不能因此改变。复用原库依赖，不要求增加独立 Container library。

## 2. 公开 source API 合同

建议在现有 RuntimeFacade 增加以下 typed seam；这些是本版建议名，不是稳定二进制导出名：

```txt
submitContainerIntent(ContainerIntent) -> ContainerReceipt
readContainerReceipt(RequestKey) -> optional ContainerReceipt
acknowledgeContainerReceipt(RequestKey) -> bool
readContainerState(ContainerQuery) -> ContainerSnapshot
readContainerAvailability(ContextToken) -> ActionAvailability
```

<code>ContainerIntent</code> 是有限 tagged union，不是 JSON patch 或任意 Operation。公共调用者只表达产品意图；ObjectId 由 Runtime 创建和返回，不让 UI 给创建对象分配 canonical ID。

共享 header：完整 CanvasTargetKey、clientId/requestId、owner deadline（沿用现有语义）；选区驱动操作携带 expected selection token，明确对象列表的操作携带完整 ObjectId。队列接收时复制意图，不能到执行时改用“当时最新选区”。目标不存在、选区已换或 binding 已变时返回明确 stale，不静默换目标。

## 3. 指令及 canonical 表达

| Typed action | 参数意义 | 选择的 canonical 路径 |
| --- | --- | --- |
| CreateSection | 明确 DocumentWorld rect 或完成的 creation gesture；已解析样式 preset | 统一使用 IntroduceWrappers，空 adoptions；不同时 InsertObjects |
| GroupSelection / WrapSelectionInSection | captured selection roots；Section title/padding/header preset | IntroduceWrappers；最近合法共同祖先及顺序由 planner 计算 |
| Ungroup / RemoveSections / ReleaseContainers | 明确 kind-filtered container IDs | 一个 ReleaseWrappers batch，完整 surviving frontier |
| MoveToContainer | roots、明确目标 parent 或 root；保持当前 world pose | RelocateObjects |
| CommitAcceptedDrop | session 最后 confirmed preview world pose + Runtime 接受的 drop target | 同一 RelocateObjects；不先 move 再 reparent |
| ResizeSectionBoundary | SectionId、local Rect2 或完成的 handle session、basis | SetSectionContent；整值 expected/replacement |
| RenameSection / SetSectionLayoutMetadata | SectionId、title 或 padding/header 及原 content token | SetSectionContent；保留未编辑字段 |
| SetSectionAppearance | typed fill/opacity patch | 已有 PatchProperties，经 Section applicability 验证 |
| Move containers / transform Group | 既有 selection transform path | SetTransforms，仅选中根；Section boundary resize 不误走此路径 |
| Default Delete | 交 common command classifier | 全部 Section 安全 Release；无 Section 走已有 destructive path；混合时提交前 UnsupportedMixedRemoval |
| DeleteSectionAndContents | 显式破坏性意图 | 已有 DeleteObjects，捕获完整删除闭包用于 RestoreObjects |

不开放“set parent\_id”按钮给平台直接写入。若 action/目标 kind 不匹配，拒绝整个意图，不按对象逐个 best effort。空 Group/Section 的恢复使用原 ObjectId 及完整 wrapper record。

## 4. 内部准备与提交接口

```txt
ReadLease:
  document binding + lifetime-owned read projection + internal generation

PlannedContainerCommand:
  one immutable forward operation
  exact touched before/after values + source dependencies
  desired final geometry and resolved order keys

AdmittedUndoableCommand:
  owner-bound PreparedApplyPlan
  verified hypothetical poststate S1 view
  complete inverse operation for S1
  measured forward/inverse wire sizes + collection sizes
  move-only HistoryReservation + reserved terminal receipt
  bound document/runtime/read generation
```

这些对象只在 Runtime 内使用，不进入 canonical wire。ReadLease 的持有不代表跨 pump 永久有效；commit 时需要验证绑定。S1 是 <code>PreparedApplyPlan</code> 的只读 staged view/overlay，不必复制全 Document，也不成为第二文档。

建议调用次序：planner.construct → semantic.prepare(F,S) → derive S1 → history.prepareInverse → normalize/measure F,U → semantic.prepare(U,S1) 验证其合法性与确切恢复 → History 预留 → owner.commit(ticket)。计量包含 envelope、guards、完整成员集、恢复记录和重复编码开销。

现有 OperationEngine 提供 prepare 和 apply，没有公开的 owner-bound commitPrepared 入口；实施应在该 owner 内增加受限 seam 或等价的单次 serialized orchestration。<b>不能</b>在检查后又调用一个会基于新状态重算 payload 的通用提交而继续使用旧逆操作。prepare/commit 之间版本变化时丢弃 ticket，以原 F 和原 guards 重验；如果仍合法则重新建立 S1/U/reservation，不自动语义 rebase。

<code>HistoryReservation</code> 为 move-only 生命周期：Prepared → Consumed 或 Released。失败、取消、异常或 close 自动释放；成功后把同一已预留记录放入原 EditorHistory。提交后加入 History 和终态 receipt 不再分配。已有 <code>commitPrepared(...) noexcept</code> 仅是接入点，不是已经满足 E01 的证明。

Undo/Redo 使用同一 coordinator 和新的 OperationId；网络重投保留原 OperationId。逆向 canonical 值必须恢复 saved preimage，不用新求逆近似替代。前后状态检查只覆盖合同规定依赖，不因无关 generation 变化直接宣告语义冲突。

## 5. Gesture 与对象编辑互斥

ContainerGestureSession 复用现有 input arbiter；token 绑定 target、PointerKey、session generation、view metrics/camera basis 和原对象读基线。可用模式为 CreateSection、MoveRoots、ResizeBoundary、AcceptedDrop；不是 Section 编辑 scope。

Move 始终从起始姿态加当前 confirmed 位移计算，不累计上一帧舍入误差。Resize 使用既有 P12 PoseConstruction 和 inverse world map，把手柄点映射到 Section local boundary；遇到不可逆或数值超域返回 NumericRange，不能 clamp 成合法提交。穿过对侧边导致宽/高非正时保留最后合法 preview，并在终态明确拒绝／取消，而不偷偷改变已接受正尺寸语义。

同一 owner 上已有 RichText editing、Image crop 或另一个 mutating gesture 时，使用既有编辑协调器明确结束或返回 Busy；容器命令不在后台强制提交未确认 IME 或裁剪。纯导航继续遵循已有仲裁。

## 6. Readback、能力与状态

ContainerSnapshot 至少包含：target、SemanticGeneration、SceneRevision、projection freshness；所查询完整 ObjectId/kind/version、父级、局部 boundary 与 world quad；直接成员数量；Group scope 和选区引用；可用 actions 与 disable reason；活动 gesture token/phase、title/readback 和背景/opacity。所有值来自同一个可解释 read basis，不混用已提交内容和旧几何。

<code>ActionAvailability</code> 分开表达 BuiltSupported、SessionAdmitted、Writable、ContextEligible、TemporarilyReady。已接受 Section wire 不代表本 build 实现了 facade、renderer 或 opcode；未知或部分实现返回 Unsupported/Unavailable。禁用原因如 MissingCapability、LockedByExistingPolicy、Busy、Stale、ProjectionUnavailable、UnsupportedMixedRemoval；不要退化成一个真假的 disabled 布尔值。

Receipt 使用请求键，区分 Queued、NoChange、Rejected/Stale、Cancelled、AlreadyApplied、CommittedPendingProjection、Applied（canonical 已提交且所需投影已就绪）。具体 enum/code 数值不在此发布。commit stamp、OperationId 和 projection token 分别返回；不把 applied 当成 saved/synced/presented。上述为新容器域回执的语义投影，不重定义现有 ProductControlReceipt、ApplyDisposition 或旧 API 的 Applied 枚举。新回执须分别携带 canonicalOutcome 与 projectionOutcome；桥接旧入口时保留原枚举含义，不把投影等待误映射为 canonical 拒绝。

## 7. 有界队列、终态与幂等

复用 CanvasControlService 的有界请求/receipt 机制；新增 domain 进入同一 owner 排序。准入前预留 outcome slot，满则 Backpressure 且未提交，不事后丢弃提交回执。每个 active gesture 预留 terminal/cancel 通路，不能让 Move backlog 阻挡 source-loss。

相同 scoped RequestKey+相同 typed payload 观察原 outcome；同 key 不同 payload Collision。新入口复用既有 retention/ack 和 high-water 防重放原则，不能在终态淘汰后把旧 request 重新执行。所有 identity 包括 target epoch，不能复用旧 mount 请求去写新文档。OperationId ledger 仍是 canonical 幂等 owner，与 Facade 请求缓存是不同层。

控制请求和 pointer terminal 不可合并丢失；仅同一有效 session 的中间 preview Move 可以按既有策略合并。首版不新增后台任务、无界线程池或第二调度器。数字队列上限继续由既有 control profile 拥有，P31 若切换 profile 必须明确绑定，不能默认无限。

## 8. Projection 模块接口

Container geometry provider 返回 ownBoundary、ownPaintBounds、subtreeVisualBounds、worldTransform、canonical order path 和 geometry revision。exact point/region query 消费同一几何投影；renderer 不独立重算成员与点击优先级。

失效输入来自 canonical ChangeSet 的 before/after plus existing hierarchy/reference indices。根 transform → descendants；子几何变化 → ancestor union；reparent/order → old/new ancestors/order；Section content →自身 boundary/title；外部 Connector 跟随 existing route dependencies。未完成子树派生工作不得发布部分 Scene revision。

可先使用现有正确的 full-rebuild recovery/reference 路径完成一致发布，但必须标记全量开销，不能称作局部优化；本轮不实施 G5。

### 8.1 ARC-CR-C01 — Preview 与已提交投影的交接

本条是同范围 Closure Review 的架构澄清，不改 P12/P13、Operation wire 或产品选择规则。Interaction 持有 preview；Scene/Render 的既有发布协调者拥有将 preview 与某个 committed projection 配对的责任。

每份可呈现的组合必须绑定同一 target、base SemanticGeneration/SceneRevision、camera/metrics basis，以及 preview session identity/revision。这些是本地派生身份，不是新增 canonical 字段。依赖 geometry 的 query/readback 必须说明使用 committed 还是 preview basis；不得把两者拼成未标识的快照。

移动 Group/Section 的 preview 是对捕获根姿态的一次替代，所有后代依该姿态组合一次；不能只移动容器背景而漏掉孩子，也不能在已经含有根 delta 的孩子 world transform 上再乘一次相同 delta。Section boundary resize 的 preview 只替代 boundary，不改变子树坐标系。具体使用根 override 还是等价的派生展开是实现选择，以上可观察结果相同。

canonical commit 后，preview 只有在仍与其捕获 base projection 相容时才可作为明确的待投影呈现继续显示。发布包含该 commit 的新 coherent projection 时，必须在同一个对读者可见的 frame/publication 交接点撤下对应 preview；禁止一帧内把新 committed pose 与旧 preview delta 叠加。恢复直接到覆盖该 commit 的较新 generation 也适用；不能只等待严格相等的旧 generation 而永久挂住 preview。

target、session、camera/metrics 或几何基线不相容时，撤下失效 preview 或保持明确的 unavailable，不将其套在新 Scene 上。投影失败期间仍遵循已有 CommittedPendingProjection：不重交 F、不追加 History、不把 canonical 成功改成拒绝。预览被撤下与命令被撤销不是同一事件。
