### Task 1: Add the reusable B-AUTH-02 hierarchy-capability validator

**Files:**
- Create: `runtime/semantic/include/canvas/semantic/hierarchy_capability_validation.hpp`
- Create: `runtime/semantic/src/hierarchy_capability_validation.cpp`
- Create/Test: `runtime/semantic/tests/hierarchy_capability_validation_test.cpp`

- Modify: `runtime/semantic/tests/CMakeLists.txt`

**Interfaces:**
- Consumes: `StagedObjectView`, `ObjectId`, `StatefulResult`, existing `requireKindVersion` where needed.
- Produces:

```cpp
[[nodiscard]] StatefulResult validateStagedHierarchyCapabilities(
    const StagedObjectView& staged,
    std::span<const ObjectId> affected_child_ids);
```

**Precondition / ownership:**
- The caller has already established the intended complete staged resulting state.
- B3 normally runs first and owns missing-parent/cycle semantics. The helper must still fail safely if an affected child or parent cannot be resolved, but must not implement cycle traversal.
- `affected_child_ids` identifies children whose final parent relation is introduced or changed by the current operation. Duplicate IDs must not change the semantic result.

**Exact algorithm:**

```text
unique sticky_parents = {}

for child_id in affected_child_ids:
    child = staged.find(child_id)
    if child is missing:
        return kObjectMissing

    requireKindVersion(child)
    on failure: return existing B2 issue

    if child.placement.parent_id is absent:
        continue

    parent = staged.find(parent_id)
    if parent is missing:
        return kInvalidReference

    requireKindVersion(parent)
    on failure: return existing B2 issue

    if parent.kind == Group:
        continue

    if parent.kind == Sticky:
        if child.kind != RichText:
            return kInvalidApplicability
        sticky_parents += parent.id
        continue

    return kInvalidApplicability

for sticky_id in unique sticky_parents:
    direct_children = staged.children(sticky_id)
    richtext_count = 0
    for direct_child in direct_children:
        requireKindVersion(direct_child)
        on failure: return existing B2 issue
        if direct_child.kind != RichText:
            return kInvalidApplicability
        richtext_count += 1
        if richtext_count > 1:
            return kInvalidApplicability

return kNone
```

Do not call `staged.allObjects()` or base `allObjects()`.

Do not scan children for Group parents; Group has no cardinality limit.

A newly staged empty Sticky is valid because it has no affected child relation requiring a cardinality failure.

**Required focused cases:**

```text
HCV-B01 root Shape -> kNone
HCV-B02 Group -> Shape -> kNone
HCV-B03 Group -> Group -> kNone when B3 topology is otherwise valid
HCV-B04 Group -> Sticky -> kNone
HCV-B05 Sticky -> RichText -> kNone
HCV-B06 empty Sticky is compatible / no false failure
HCV-B07 Sticky -> Shape -> kInvalidApplicability
HCV-B08 Shape -> RichText -> kInvalidApplicability
HCV-B09 Connector -> Shape -> kInvalidApplicability
HCV-B10 Sticky with second direct RichText -> kInvalidApplicability
HCV-B11 same staged Sticky + RichText result is independent of ObjectId ordering
HCV-B12 existing Group parent -> new/staged child succeeds
HCV-B13 existing empty Sticky parent -> one staged RichText succeeds
HCV-B14 existing Sticky with one RichText + staged second RichText rejects
HCV-B15 Reference/Indexed parity + no mutation/index rebuild consistency
HCV-B16 no `allObjects()` call; self-contained Group relation resolves from overlay; Sticky relation may use direct `children(sticky)` only
```
