## 5. Type-Directed Fixture Decoder Contract

The C3 decoder is verification-only and must not become Product JSON ABI, protobuf format, storage format, sync format, or public runtime ABI.

### 5.1 Exact f64 carrier

For a semantic field typed as f64 / double by Current schema/IDL:

```text
f64:<16 lowercase hex digits>
```

means exact IEEE-754 binary64 bits.

Decoder rules:

1. Require exactly 16 lowercase hexadecimal digits.
2. Parse to unsigned 64-bit bits.
3. Reconstruct `double` by bit-preserving conversion (`std::bit_cast` or equivalent), never decimal conversion.
4. Do not canonicalize `-0` in the fixture decoder.
5. Do not reject NaN, +Infinity, or -Infinity in the fixture decoder.
6. Preserve the decoded raw bits in a verification-only pre-semantic projection so CONTROL_REVIEW can prove the intended invalid stimulus reached the production semantic lane.
7. A malformed carrier, unsupported scalar width, or carrier used at a wrong typed numeric location is a **HARNESS_ERROR**, never a Product `REJECTED` result.

Frozen representatives:

```text
qNaN = f64:7ff8000000000000
+Inf = f64:7ff0000000000000
-Inf = f64:fff0000000000000
-0   = f64:8000000000000000  (synthetic decoder test)
```

### 5.2 String safety

`f64:` is not a generic magic prefix. A semantic string field containing text such as:

```text
f64:7ff8000000000000
```

remains an ordinary string. Type comes from accepted semantic schema/IDL, never from the prefix alone.

### 5.3 JSON parser implementation constraint

C3 may use generic JSON/protobuf JSON-DOM primitives available to the verification tool build, but fixture decoding must manually map the accepted C fixture contract into Axiom semantic types. It must not call Axiom Product `SemanticCodec` or production protobuf DTO decoding to turn the verification JSON fixture into expected/semantic truth.

This is a harness implementation choice, not a new Product serialization contract.
