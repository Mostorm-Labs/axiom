## Bounded capability and property profiles

General actions: Fit, Delete/Section release, lock/unlock, order, transform, size and appearance use existing owner preconditions. Delete performs only a pure OperationEngine.prepare query with a noncolliding probe identity; it neither allocates an operation ID nor applies/reserves/records History. Single-only commands remain unavailable for multi-selection. Locks, active input/text/Crop/creation/transform sessions, unavailable geometry and non-normalized formal selections are reported explicitly. Capabilities are eligibility snapshots, not a guarantee that future command admission/resources will succeed; actual commands retain their original authoritative validation and History path.

Group/Ungroup, bulk properties, Snap and Alignment remain NotImplemented. The new Wrap shortcut is OutsideBatch. FC08's existing dedicated Wrap/Release/Reparent commands and panel remain in place; this batch adds no such mutation. Specialized Text and Image/Crop owners are retained.

The initial property profile is field1 visibility, field2 lock and field3 opacity, all already read by existing APIs. A read-only Semantic accessor forwards the exact existing validator applicability predicate; its rules, schema, defaults and registry are unchanged. Visibility/lock reuse existing effective Scene values. Absent values use the same accepted default table that canonical normalization already elides (opacity=1 included), exposed by a read-only Semantic accessor. The existing eight-field normalization default behavior remains covered by its unchanged regression. Unknown/non-applicable values stay unavailable. Uniform exposes a value only when every root applies and agrees; Mixed and Partial never lend primary's value to other roots. Applicable/known counts and mixed-within-partial state are explicit. Fill/stroke/font/text-format aggregates and bulk writes are not added.

Router caches capability/revision facts, not an authoritative ID list, and rechecks Runtime tokens/capability at action submission. Existing control-service captured selectionRevision still fences queued actions. Specialized active text editing uses its existing session authority. Rendering/refresh and blocked actions create no Document operation or History entry.
