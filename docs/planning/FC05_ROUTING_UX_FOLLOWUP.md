# FC05 连线预览与折线布局跟进

用户在 2026-10-25 明确要求：拖动时保持真实连接线；无遮挡时将折线中段放在两端之间；
点击连接点生成同类型对象时，能够水平或垂直直连就不增加折点。
本次调整共享 Runtime/Scene/Render，Windows/Web 继续使用同一实现。

## 原因与修复

1. 旧作业即使处理简单场景，也固定在端点解析和障碍物收集后让出执行机会。
   预览每次 pointer 更新会使旧作业失效，所以连续移动常常一直显示 Pending 诊断弦。
   现在简单路线在同一有限 quantum 内完成认证，预览缓存当前输入的终态结果。
2. 搜索图之前只有出线点、障碍边缘和域边缘，没有中线偏好。
   现在先尝试轴向直连，再尝试平行端口的中线折线和 L 形候选；每段都必须通过同一
   膨胀障碍物检查。候选被挡后继续原有有界 A*，不牺牲避障来强行居中。
   一般搜索、候选尝试共用原有累计工作预算；取消及输入代次失效规则保留。
3. 点击命中连接点圆圈的位置并不一定等于真实语义端口。零长度 Down 尚无有效的
   preview record，因此新对象定位现在单独解析语义端口，并校正垂直于出线方向的坐标。
   保留同类型生成、相对侧端口和 Connector + 对象一次原子 History。
4. 按本次用户展示要求，Pending 保留原线型和颜色，终态无路由/超预算仍用橙色虚线
   诊断。Pending 状态不伪装成 Ready，也不承诺尚未完成的避障检查已经通过。
   原先关于 Pending 橙色虚线的展示说明由本次用户要求替代，旧证据不改写。

派生算法 revision 为 2；没有修改 canonical ConnectorContent、schema 或 SDK locks。

## 真实拖动折线修正

用户在 `edccc2db` 人工复测中仍观察到拖动时为斜线、松手后才为折线；该次结果记录为 FAIL。
新一轮人工复测单独保持 PHYSICAL_PENDING，不改写这个失败。

根因是 `connectorGeometry(..., defer=true)` 在路由器已返回 Ready 四点折线后，仍无条件
把 route 改写成两个端点。此前回归只断言 Ready 和端点位置，未检查路由形状与实际像素。
现在延迟适配直接沿用作业路径；尚在计算时保留带 Pending 状态的正交示意路径，不能
把该示意当作完成避障。普通小场景继续在第一 quantum 中返回认证的完整折线。

新增验证覆盖连续三次 Move 的真实 Runtime → FramePlan → Skia 光栅输出：中间折线段
像素存在，斜线位置为空白；Move 不写 canonical。另对照 Up 后的完整顶点、一次 History
和取消语义，避免只检查派生几何函数。41 项 native/WASM 语料同时覆盖作业与延迟适配，
包含实际跨 quantum 的 Pending 四点折线。

Up 对照还发现没有文字布局服务时，派生路由推进 Scene 版本后重建会拒绝旧版本。
现在 deferred routing 也使用已有版本适配器，保持 Scene 版本与 Semantic generation 独立。
相关证据在 `fc05/evidence/live-polyline/`；保留原 Image 旧期望失败，不修改历史 Golden 或 Gate。

## 三角形上下端口直连

用户人工发现上下对齐的三角形通过顶点连接时仍出现侧向绕折，记录为 FAIL。
三角形顶点有多个合法支持法线；快速候选之前在第一个逃逸组合找到有效路线后立即返回，
因此侧向出线先于竖直零折点候选被接受。

现在快速候选与 A* 都按完整路径的长度、折点数、字典序共用比较逻辑，跨逃逸组合选优。
只有经碰撞检查的轴向零折点路径达到全局长度下界时才能提前返回；其他组合继续共用
原有总预算。端点位置、合法法线和障碍物安全距离保持原合同。旧的折点剪枝现在也先
比较长度下界，避免用较长候选的折点数剪掉更短路径。

上下两个方向的三角形直连、预览与实际点击创建均已覆盖；Rectangle/Ellipse/Triangle/
Sticky 四种对象的四个连接点扩展为 16 组点击对照。新增中间有障碍物时仍需绕行的反例。
`fc05/evidence/triangle-ports/` 保存 RED、CTest 与 44 项 native/WASM 对照；历史失败不改写，
新版本真实鼠标/触摸复测保持 PHYSICAL_PENDING。
