# Lasso／矩形框选／统一选择语义：已确认设计记录

## 1. 来源与状态

用户已确认上一轮设计，并要求开始源码对照与第一批实施包。本记录整理该确认，不扩大为产品 Gate PASS，也不把先前设计草案中的所有字段视为已经存在的 ABI。

源码观察基线：`2fee75f66a7f96f6aac834228ede372a9abda59a`。详细事实见 `02-source-gap-audit.md`。

## 2. 已确认的行为

- 点选、矩形框选、自由套索共用 Runtime 的正式选区所有者与目标归约规则。
- 区域选择采用相交即选中。不加入按拖动方向切换“完全包含／相交”的规则。
- 默认替换；Shift 在 Down 时锁存为追加并集，不能用 toggle 代替。
- 点选工具在真正空白处拖动启动矩形框选；空白点击在 Up 时清空，Shift 空白点击保留。
- 显式矩形／自由套索工具在可获取画布输入的位置开始区域手势，即使起点在对象上也不拖动对象；UI、文本编辑、Crop 等已有独占所有权仍优先。
- 移动仅更新轮廓与候选高亮；Up 时重新验证并一次性发布正式选区。
- 有效空区域：普通模式清空，追加模式保留。无效微小手势：保持原选区。取消：清除本次临时状态，保留仍存活的原选区，不恢复已删除对象、不覆盖后来产生的选区。
- 自由套索自动闭合；自交采用 even-odd。预测输入不得决定最终成员集合。
- 相机、目标绑定、surface／metrics 或 scope 不兼容变化使当前区域手势取消；文档变化可以在一致读取上重查，不能提交混合版本结果。
- 新区域命中排除 hidden／locked。现有点选用于检查／解锁等策略不能被无差别改写。
- Select 与 Hand 切换保留完成后的正式选区；Hand 时控制柄不接收编辑输入。
- 选择是本地编辑器状态，不修改文档、对象、Operation Log、History 或同步数据。

## 3. 几何与层级

空间索引/AABB 只找候选；最终判断由真实可选择几何完成。点选和区域选择可以具有不同几何查询方式，但必须共享对象身份与容器归约原则。

沿用 Section、Group、Sticky 已有的产品行为。普通命中 Sticky 内部文字应归约外层 Sticky；Group scope 复用现有规则；Section 不自动被当成 Group。不得把同一可变操作的祖先和后代作为重复操作根。

## 4. 第一批交付边界

交付公共区域会话、Replace/Add 发布、空白拖动、候选预览、取消与工具切换，以及工具入口和真实输入接入。

以当前 Shape 的 Rectangle／Ellipse／Triangle 建立端到端精确几何证明；复用已经存在且能证明正确的其他对象 provider。不以其他对象尚未接入为理由拖延公共链，但也不把缺失 provider 当作 Empty/NoHit。必须报告具体 coverage 与 Partial/Unsupported 状态，不能声称所有对象已覆盖。

保留已有 Section／Group／Sticky／Connector／Text／Image 行为，增加针对本批接入的回归。复杂笔迹、擦除后几何和完整容器区域选择覆盖继续列入第二批，不删除责任。

多选的正式轮廓必须表现整个选区。未实现的批量编辑与多对象变换不得只作用于 primary 后假装成功；应禁用或返回 Unsupported。已有能安全消费完整选区的命令保留，但需要实际证明。

## 5. 暂不加入

完整批量属性编辑、Group/Ungroup 新命令、全量 Selection Summary、Snap/Alignment 新能力、未来对象类型及完整 FC-08 302 变体 runner，不作为本批开工前置条件。

不改 canonical schema、Section Operation 17/18、历史 descriptor lock、旧预期或既有证据。Region 会话只保存瞬态快照，不引入第二份正式 SelectionState。
