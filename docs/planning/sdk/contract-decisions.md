# SDK boundary and compatibility — review candidate, not Current

All new interfaces below are review candidates. `docs/api/RUNTIME_C_API_CONTRACT.md` explicitly declares an **Accepted contract baseline**: it fixes the C ABI direction, generation handles, borrowed input/callback lifetime, caller buffers and command-batch undo-intention semantics. Its AR-0 clarification supersedes the old canonical Transaction wrapper and requires later manifest evolution. Existing C V1 header and manifest are immutable inputs; adding proposed names here creates no ABI. `docs/notion/authority/05-runtime-architecture/README.md` identifies the architecture source set. `docs/notion/authority/05-runtime-architecture/axiom-architecture-baseline-v0.4.md` replaces obsolete Transaction-centric wording with Operation ownership. The 08 index identifies physical platform scope but is a dated mirror, not proof that all interface details have been accepted. ICF-00, ICF-01, ICF-02 and ICF-05 local mirrors explicitly say **Current Proposed Freeze Candidate**, not accepted freeze. See the package authority lock for content hashes and unresolved acceptance.

## Reviewable first public API proposal

Names below describe capabilities and are not an accepted C declaration. The exact versioned wire-compatible shapes, supported field tags and ABI error mapping must be accepted before P32.

1. `runtime_create(config, callbacks, out_runtime)`, proposed `runtime_close(runtime, request, out_receipt)`, existing V1 `runtime_destroy(runtime)` and `runtime_capabilities(runtime, out)`: validate version/size; stale, wrong type, foreign instance and repeated destroy have stable errors; owner retains no borrowed input after return. Proposed close rejects new ingress and waits for platform/data barrier; immediate success is allowed only when already drained. Accepted V1 `runtime_destroy` still requires all child documents/views closed and surfaces detached and must fail without implicitly destroying them otherwise; the new close must not silently change this existing contract.
2. `document_open(runtime, full_document_id, config, out_document)` and `view_create(document, config, out_view)`: one each for first version; wrong/stale runtime/document and additional active attachment are rejected; not a promise that current `open()` already implements snapshot restore.
3. `target_query(view, out_binding_identity)`, `control_submit(view, binding, request_id, expected_generation, typed_command, out_admission)`, `control_receipt(view, request_id, out_result)`: explicit target and full identity; command values are validated with explicit conversion tables; final result reports exact applied targets and failures.
4. `selection_copy(view, expected_revision, buffer, capacity, required, observed_revision)`, `selection_property_query(view, field, snapshot)`, `permission_context_set(runtime, context)`, `selection_property_submit(view, request_id, stamp, field, value, exact_ids)` and `selection_property_receipt(view, request_id, result)`: proposal above, with caller-owned capacity-probed buffers and all applicable fields/identity retained. Unknown permission blocks writes.
5. `input_submit(view, registered_source, generation, samples)` and `frame_opportunity(view, binding, timing, out_work)` plus `frame_complete(view, work_identity, actual_feedback)`: adapters map real existing source/role tokens; the exact public work representation remains undecided.
6. Text, Image, Connector, Sticky, Section and Group typed commands are Facade adapters, not new owners. Snapshot/export/restore, resource callback and IME/public geometry remain mandatory later-slice capabilities; no early stub can satisfy their exit criteria.

## Decision handback

Before SDK-01 P32: accept API/ABI extension/version, handle/thread/error/lifetime and explicit target semantics, multi-selection permission/receipts and migration ordering, and freeze independent API01–API06/09 oracles. The DataBridge/close Proposed Freeze Candidate must be accepted or reconciled before SDK-02 claims document durability or recovery. Runtime surface/work identity and actual presentation mapping need platform-owner acceptance before SDK-03/04 qualification. The 32-bit handle reuse strategy and exact per-API threading cannot be inferred from the V1 declarations alone. These are concrete proposed deltas; none is silently Current.
