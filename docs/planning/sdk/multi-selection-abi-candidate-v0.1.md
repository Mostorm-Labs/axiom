# SDK-01 multi-selection C ABI candidate v0.1 — DRAFT, not accepted

`candidate-multi-selection-v1.h` is a concrete, compilable design input only: it is not an installed header, a V1 manifest change, a linked implementation, a P32 authorization or a Gate result. New identifiers and numeric values are provisional. The accepted base header stays byte-for-byte unchanged. If review rejects this ABI, publish a new candidate rather than changing accepted values later.

## Semantic and ownership basis

[D06-B P23 acceptance](https://app.notion.com/p/4074c57a590c81d9b124cd243e44f205) records an eligible subset only when exclusions and reasons are visible; applicable but locked, denied, stale, missing or indeterminate roots reject rather than being classified as inapplicable. Mixed and partial are independent. It accepts no public ABI. Its Notion page identifies itself as scope-limited Current; connector verification metadata is `unverified`, so an accepted P31 must bind the exact authoritative capture rather than this URL alone. [Facade v0.2](https://app.notion.com/p/3c84c57a590c81b7a5d8d15997502eaf) separates Product Shell control from DataBridge, treats Canvas as session state and requires non-reentrant coarse product events. The V1 C contract provides generation handles, borrowed inputs, caller-owned outputs, no exception across ABI, and one user-visible undo intention rather than a generic wire Transaction.

RuntimeComposition owns the single `SelectionSession`, existing Facade, `MultiSelectionPort`, Semantic/Scene and History. The SDK adapter translates fixed-width values, validates handles/versions and calls those owners. It must not own canonical selection, copy the document model, build canonical operations in the UI, or use a second History. Windows and Web consumers remain on the current internal port until an equivalent public path is verified; then both migrate before that accessor is hidden.

## Public values and lifetime

- Every call is owner-thread-only in the candidate; another thread must use an explicitly defined platform ingress, never directly mutate. Reentrant mutation from a callback is rejected. `CanvasStatus` reports invocation success/failure, while the versioned admission/terminal receipt reports whether a command is queued, applied or rejected. A queued response never means applied or presented. `canvas_sdk_runtime_pump` proposes the existing owner-safe no-input control opportunity; it is not a frame-present or durability acknowledgement, and its queue/deadline semantics require accepted P20 bindings.
- Existing V1 `CanvasRuntimeHandle`, `CanvasViewHandle`, `CanvasObjectId` and full `CanvasClientId` domains remain unchanged. A `CanvasSdkMultiTokenV1` is a 16-byte opaque, process-local observation capability, not an exposed raw Scene or Semantic generation. It binds Runtime instance/lifetime, View, attachment, selection, semantic and scene revisions, permission revision and queried field. Cross-runtime, wrong-view, closed, released, evicted, reattached or stale tokens fail closed. It is neither durable nor a second selection owner.
- The adapter may use a bounded Runtime-owned token table storing only the exact underlying observation stamp and field; it re-reads the real projection and checks expected eligible roots at submission and execution. Token exhaustion must return explicit resource/capacity failure, never evict a token in a way that makes it alias a newer observation. Token allocation/release and generation wrap need a concrete acceptance and OOM test; this is a design choice, not an existing implementation claim.
- Translate full 128-bit ClientId through an owner-scoped collision-free, bounded mapping if the underlying control lane still accepts uint64 clients. Never truncate or hash without collision detection. Request IDs are nonzero and monotonically checked per full client; duplicate, expired and queue-full outcomes remain distinct. Mapping and token lifetime terminate on close.
- `capture` writes a caller-owned metadata struct for one field and returns a token; `copy_roots`, `copy_eligible`, `copy_excluded` and `copy_uniform_value` return values from that same valid observation. `copy_root_value` reads a single eligible root's actual property through that same token, enabling verification of distinct mixed styles without exposing the object store; the root must belong to this snapshot and the relevant read must be authorized. Unknown read permission/provider state rejects rather than returning a guessed value. Support, current availability and permission are independent fields: unknown query/provider state is not unsupported, and permission unknown is not denial or allowance. Caller first queries required capacity and then copies. Any stale token, wrong handle, invalid pointer/size, overflow or insufficient capacity returns an error without a partially written result; `required` is the only explicitly permitted size output on buffer-too-small. Arrays are caller-owned. A uniform value is over eligible roots only; a partial projection still explicitly reports eligible/total and exclusions.
- `CanvasSdkMultiValueV1` carries exact typed bool/f32/color, semantic fill and full stroke geometry with f64 width/miter/dash, and known semantic enum values. The optional dash input is borrowed only during the call and must be copied before enqueue. For output the SDK writes dash data into caller-provided storage and may set `value.dash_segments` only to that storage. Missing/mixed values return an explicit result, never the primary object's value. Unknown field/kind/enum, malformed boolean, reserved bits, overflow, NaN and out-of-range payloads are rejected according to existing semantic validation; no schema/field ID changes.
- Fixed array elements `CanvasSdkMultiExcludedV1` and 16-byte token are not extensible; their exact Windows x64 and WASM32 layouts must be verified before acceptance. Other extensible records start with `struct_size` and `abi_version`, without embedding a second extensible struct by value. Unknown future values fail closed and old V1 fields/numeric values remain unmodified. Struct pointer alignment, integer overflow, no partial output, calling convention, dynamic library exports, exception translation and cross-CRT allocation require real target tests.
- Candidate error mapping: wrong handle domain uses `kCanvasStatusWrongHandleType`; absent/destroyed/foreign handles use `kCanvasStatusInvalidHandle`; unknown ABI uses `kCanvasStatusAbiMismatch`; malformed arguments use `kCanvasStatusInvalidArgument`; insufficient output capacity uses `kCanvasStatusBufferTooSmall`; stale/released/evicted observation tokens use `kCanvasStatusSequenceError`; unavailable owner uses `kCanvasStatusUnavailable`. A validly invoked submission that is not admitted returns an explicitly rejected/stale/queue-full **admission receipt**, with the precise failure and no mutation, rather than pretending the command was applied. These mappings are candidate decisions subject to compatibility review; exact platform errors and retries require P20 tests.

## Command sequence and field-preserving patches

1. Owner configures permission explicitly. Unconfigured and unavailable are not allow; local-single-user mode is opt-in and a change invalidates earlier observation tokens. A future external permission provider is not invented here.
2. Caller captures projection, reads exact eligible/excluded roots and typed reason, and makes any partial-subset operation visible to the user. The candidate exposes only `NotApplicable` as an exclusion. Locked, denied, stale, missing or provider-unavailable applicable roots reject the entire eligible cohort before write.
3. Caller submits exact eligible IDs and the capture token with full ClientId/request ID, explicit patch mask and typed value. When partial, the candidate requires `kCanvasSdkAcknowledgePartial`; omitting it rejects the command. This flag is not itself proof that the UI displayed the subset: each real consumer must show eligible/total and exclusions and obtain the user's intended action. Admission validates token, permission, field/type, identity, target set and resource capacity; at execution the owner checks them again. Omitted/extra/duplicate/stale IDs fail; neither primary-only nor silently shrinking E is permitted. Terminal receipt reports changed/unchanged/skipped IDs through caller buffers and never reports changed IDs during pending.
4. `kCanvasSdkPatchReplaceField` replaces the *entire* semantic field, and cannot be combined with leaf bits. Stroke leaf bits explicitly change color, width, cap, join or dash while retaining every unselected leaf **for each eligible root**, even when roots have different existing styles. `NoStroke`, invalid masks and absent prerequisites must be rejected rather than inventing a style. A user-visible Undo unit targets the committed roots; stale requests reject and must be explicitly refreshed/retried, as the user decided on 2026-10-29.

**Current source gap:** `MultiSelectionPort::submitProperty` submits the same whole `semantic::PropertyValue` for every eligible object; it does not provide the proposed per-root stroke leaf patch. Its projection also does not provide the proposed authorized per-root property read. A wrapper that sends a primary/uniform stroke style would overwrite distinct root fields. SDK-01 must either implement per-root read/prepare/validate and one existing semantic `PatchPropertiesOp` through Runtime/History owners with D06-B admission and real failure tests, or return this required feature as blocked. The candidate header does not implement that behavior, and the capability must not be reported as supported merely because this declaration exists. One typed multi-target Operation does not establish the unresolved D07 multi-Operation OOM guarantee.

## Compatibility and required proof

The candidate adds symbols/types beside V1 rather than editing V1 numerics/layout. Whether these names, value-kind mappings, version negotiation and token representation are accepted belongs to ABI/architecture review; semantic enum conversion must be explicit, not a direct `static_cast`. SDK-01 must test C/C++ consumers against the installed header and real exported library, including no internal include leakage, all listed ID/stamp/capacity/error cases, unknown permissions, locked and stale roots, per-root leaf preservation, changed/unchanged/skipped receipts and Undo. Execute actual Windows and Chrome/WASM Debug UI migration paths before hiding the port. A target compile of this draft header is only structural evidence. Missing MSE-20/23/26 real provider/fault paths and D07 OOM remain separately visible and cannot be replaced with a fake provider.

The local candidate layout probes observed an 8-byte pointer on Windows x64 and a 4-byte pointer on wasm32; several struct sizes and offsets happened to match. That coincidence does **not** permit raw cross-platform struct copying or persisting `dash_segments`. Web bindings must translate fields and copy pointed-to data explicitly. The measured layouts are candidate observations, not accepted ABI goldens or a browser execution result.

The current v0.2 P31 package predates this document; a successor must content-address the accepted exact candidate, test/oracle fixtures and source-owner scope, then run its required preflights. Neither this document nor the accompanying compilation exercises authorizes SDK-01 P32.
